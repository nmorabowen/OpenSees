# ADR-94 R4 -- integrator x tangent matrix
> Regenerated on `wp/94c-numerics` (build `3622d6214`), which is the first refresh
> since `wp/94a-fail-loud` (`229842f7f`). The diff against the previous table
> therefore spans THREE work packages -- `wp/94b-statics` (per-instance `Stiffness`,
> so the assembled tangent is no longer the last Gauss point's), `wp/94d` (the
> Hoek-Brown composite yield function, #806) and `wp/94c` (one Voigt shear-slot
> convention, the Drucker-Prager gradient fix, the live apex return) -- and a row
> that moved cannot be attributed to any one of them by this table alone.
> Attribution established for the rows that did move:
>
> * **VonMises `Backward_Euler`** -- `|f|max` unchanged (1.41e+01); iterations
>   21 -> 11 (`Continuum`, both `Numerical_*`) and 21 -> 17 (`Secant`). `wp/94c`:
>   with the Voigt convention the consistency scalar `n:(E:m)` is right, so the
>   local Newton converges in about half the work. Same answer, less of it.
> * **DruckerPrager** -- every cell IDENTICAL. The B4 gradient fix does not show
>   at this table's N=3 resolution; it shows on the material-point decks
>   (`tet/dp/BE/default`: committed `|f|` 9.2e-07 -> 7.3e-12, stress moved 2.7%)
>   and in `test_adr94_components` (Continuum-vs-Numerical tangent mismatch -> 0).
> * **HoekBrown** -- the large `|f|max` moves (e.g. 4.09e-12 -> 5.35e+03) and the
>   ok -> refused flips are `wp/94d`, not `wp/94c`. Proof: the `Forward_Euler`
>   rows moved too, and `wp/94c` touches no code Forward_Euler executes. **The
>   `f_hb` oracle in `tests/test_adr94_matrix.py` is still the PRE-`wp/94d` split
>   form** (`if arg > 0 ... else sigma1-sigma3-sigci*s`) rather than the composite
>   `max(f_shear, f_tension)` the material now evaluates, so the HoekBrown `|f|`
>   column is measuring a different function from the one being solved. That is
>   `wp/94d` debt, left for the owner rather than silently changed here.
> * **MohrCoulomb `simple_shear` `Backward_Euler`** (ok -> refused, `|f|max`
