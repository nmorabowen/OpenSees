# ADR-94 H10 — Hoek-Brown drift: this tree vs `jaabell/ASDP`

Generated by phase R1-C, 2026-09-07, worktree `asdplastic-review-plan-62585c`.
Command: `git diff jaabell/ASDP -- SRC/material/nD/ASDPlasticMaterial3D/YieldFunctions/HoekBrown_YF.h
SRC/.../PlasticFlowDirections/HoekBrown_PF.h SRC/.../HoekBrown_Utils.h
SRC/.../HoekBrown_ParameterTypes.h`.

**Only `HoekBrown_YF.h` differs.** `HoekBrown_PF.h`, `HoekBrown_Utils.h` and
`HoekBrown_ParameterTypes.h` are byte-identical between this tree
(`e65e89203`, 2026-05-10) and `jaabell/ASDP` `60d9b9b23` (2026-05-12) — the
upstream campaign's row 1.5 (assuming we were ahead) is wrong in the
direction but the file list it names is otherwise fine.

## (a) What changed, function by function

**`YIELD_FUNCTION`.**
- *Ours*: two-branch `if (arg > 0) { standard pow(arg,a) } else { sigma_xx -
  ish tension-cutoff branch }`, `arg = mb*sigma3/sigci + s` (sigma3 the
  geo-frame, compression-positive minor principal stress). The `else`
  branch computes `sigma_t = -s*sigci/mb` but **never uses it** — it is a
  dead local, the actual returned value is `sigma1 - sigma3 - sigci*s`. A
  large historical comment block (jaabell's composite, reproduced below)
  sits above it, entirely commented out — a stale copy of the *other*
  tree's code, not a live implementation.
- *jaabell's `ASDP`*: a single-branch composite. `arg_safe = max(arg, 0.0)`
  is clamped **before** `pow`, so `f_shear = sigma1 - sigma3 -
  sigci*pow(arg_safe, a)` is evaluated unconditionally (never NaNs even
  when `arg < 0`). `f_tension = sigma_t - sigma3` (a Rankine cutoff on the
  geo-frame minor principal stress, using `sigma_t` — not dead here).
  Returns `max(f_shear, f_tension)`. jaabell's own comment proves
  continuity: at `sigma3 = sigma_t`, `f_tension = 0` and (on the HB
  envelope) `f_shear = sigma1 - sigma_t`, i.e. the two surfaces meet
  smoothly at the tensile cutoff — no case split, no discontinuity.
  Symmetrically, jaabell's tree carries what WE have live (the if/else
  version and `CHECK_APEX_REGION`/`APEX_STRESS`/`yf_has_apex`) as dead,
  commented-out code, i.e. an intentional supersession, not a stray leftover.

**`YIELD_FUNCTION_STRESS_DERIVATIVE`.** Identical in both trees — numerical
central-difference derivative through the same `YF` call, so it
automatically differentiates whichever branch/composite is live. No drift.

**`CHECK_APEX_REGION` / `APEX_STRESS` / `yf_has_apex<HoekBrown_YF<...>>`.**
- *Ours*: **live**. `CHECK_APEX_REGION` flags `p = getI1()/3 < sigma_t *
  1.01`; `APEX_STRESS` returns the hydrostatic state `(sigma_t, sigma_t,
  sigma_t, 0,0,0)`. `yf_has_apex` is specialized `true_type`.
- *jaabell's*: all three are commented out (`yf_has_apex` defaults to
  `false_type` via the primary template).
- **This is functionally moot either way** — see the DP section of
  `_adr94_hlist_R1C.md`: the `ASDPlasticMaterial3D.h` Backward_Euler call
  site that would act on `check_apex_region()==true`
  (`ASDPlasticMaterial3D.h` ~2093-2161) has its entire corrective body
  commented out. So whether `yf_has_apex<HoekBrown_YF>` is `true` or
  `false` changes nothing observable today: `true` just means the dead `if`
  block is `if constexpr`-compiled in and immediately no-ops; `false`
  compiles it away. `CHECK_APEX_REGION`/`APEX_STRESS` being "implemented" in
  our tree is therefore cosmetic completeness, not a behavioural
  advantage — a claim worth stating plainly since a naive read of the diff
  makes it look like we are ahead on the apex handling.

## (b) Measured behavioural difference, tension vs compression

Measured on realistic rock parameters (`sigma_ci` = 50 MPa, `mi` = 10, GSI =
60, D = 0 ⇒ `mb` = 2.3965, `s` = 0.011744, `a` = 0.502841, textbook tensile
strength `sigma_t = -s*sigci/mb` = **-245.02 kPa**, rock-mass UCS `sigci*s^a`
= **5350.43 kPa**), driven through a single-element material-point test
(`tests/test_adr94_hlist_hb.py`):

- **Compression: the two trees agree, exactly.** A compression path never
  drives `arg <= 0` (confinement only makes `arg` larger), so both the
  if/else standard branch (ours) and `f_shear` (jaabell's) are the *same
  formula* evaluated in the *same* regime — `max(f_shear, f_tension)`
  reduces to `f_shear` whenever `f_shear` corresponds to an admissible-side
  evaluation with `sigma3` well above `sigma_t`. Measured: uniaxial
  compression converges to exactly `-sigci*s^a` = -5350.43 kPa (rel. error
  < 1e-6); a confined triaxial path stays comfortably admissible under the
  identical `arg>0` closed form. No port changes this.
- **Tension: the two trees diverge, and ours is measurably wrong.** Driving
  a uniaxial-stress tension path (lateral faces free) to 3x the theoretical
  tensile strain shows our tree's committed stress **overshoot the textbook
  tensile strength by a factor of `mb`** (245.02 kPa expected vs 587.19 kPa
  = `sigci*s` measured — 2.397x, and `2.397 = mb` is not a coincidence: it
  is exactly the ratio between the `else`-branch zero `sigci*s` and the
  `arg=0` boundary value `sigci*s`/`mb`… i.e. the two branches' zeros are
  offset by precisely the `mb` factor buried in `arg`'s definition). Worse:
  the analysis then **stalls** (`analyze()` returns -3) right at that wrong
  plateau, printing `PLASTIC INCONSISTENCY - ELASTIC STEP! (dLambda +
  deltaLambda < 0.0)` — the H7 fallback firing because the cutting-plane
  Newton, having converged near the `else`-branch zero, cannot find a
  further-admissible direction on the next step's larger elastic predictor.
  jaabell's composite has no such discontinuity by construction (the max()
  of two continuous surfaces), so a port would be expected to fix both the
  wrong plateau value and the stall — untested here since fixing is out of
  scope for this review (D1).
- Pinned by `tests/test_adr94_hlist_hb.py::test_H10_hb_tension_locks_onto_wrong_plateau_then_stalls`
  (the defect) and `::test_H10_hb_uniaxial_compression_matches_closed_form_ucs`
  + `::test_H10_hb_triaxial_compression_stays_admissible` (the agreement).

## (c) Recommendation on port direction

**Port jaabell's composite into this tree** (owner decision D4 still needs
a direct exchange with José per the ADR-94 plan, but the technical case is
one-sided):

1. jaabell's version is strictly more correct on tension — continuous by
   construction, with the discontinuity above measurably wrong on ours
   (a `mb`-factor overshoot of the tensile strength, plus an analysis
   stall) and zero cost on compression (the two are identical there, so a
   port changes no compression deck's answer).
2. jaabell's version is the *later* commit (2026-05-12 vs our 2026-05-10) —
   this is not a case of the fork having diverged for a reason; it is
   simply one Hoek-Brown edit behind on a feature only introduced two days
   after our copy was taken.
3. The apex plumbing (`CHECK_APEX_REGION`/`APEX_STRESS`/`yf_has_apex`) is
   inert on both trees today (the `ASDPlasticMaterial3D.h` call site is
   dead code), so porting jaabell's version loses nothing there — and if
   the call site is ever un-commented (a separate, larger fix, not in this
   ADR's scope), jaabell's `f_tension` Rankine surface is the natural apex
   target anyway (`sigma_t` is a first-class term in his composite, merely
   a dead local in ours).
4. No other file in the Hoek-Brown family (`HoekBrown_PF.h`,
   `HoekBrown_Utils.h`, `HoekBrown_ParameterTypes.h`) has drifted, so the
   port is a single-file, single-function change with a small, well-scoped
   diff — cheap to review and to no-AI-traces-port per the upstream
   campaign's rules.

This ADR does **not** perform the port (D1: review + verdict + fix *plan*
only). The fix belongs in its own `wp/94x-<slug>` branch per §7 of the
review plan, gated on the D4 exchange with José (do not guess at his
intent for the historical if/else block he chose to keep as a comment
instead of deleting).
