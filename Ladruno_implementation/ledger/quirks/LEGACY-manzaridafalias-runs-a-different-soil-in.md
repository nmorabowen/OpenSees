### `ManzariDafalias` runs a different soil in parallel/after-restore than in serial -- the wire format has no slot for `m_Presidual`
- **Bites:** any `OpenSeesMP` parallel run or database (`FileDatastore`/`recvSelf`) restore of a `ManzariDafalias` (or `ManzariDafalias3D`/`PlaneStrain`) material at low confinement. The worker/restored copy silently runs with the "residual pressure" apparent-cohesion constant `m_Presidual` at **0** while the serial process beside it runs at **1.01 kPa** (`P_atm = 101`) -- a different soil, same deck, same tag, no error, no warning. Below ~10 kPa confinement this is not a rounding difference: the ADR-86 audit measured the model's own bounding-surface identity `η_end = M^b(ψ_end)` departing **+20 %** at p₀ = 1 kPa when `p_r` is present vs. absent.
- **Why:** `sendSelf` serialises `static Vector data(97)` with `m_Pmin` at `data(96)` (`ManzariDafalias.cpp:636`) and **no slot at all for `m_Presidual`**. On the broker path (`FEM_ObjectBrokerAllClasses::getNewNDMaterial`), the class-tag/null constructor runs first -- it sets `m_P_atm = 0.0` and then calls `initialize()` (`ManzariDafalias.cpp:835-836`: `m_Pmin = 1.0e-4*m_P_atm; m_Presidual = 1.0e-2*m_P_atm;`), so at that moment `m_Presidual = 1.0e-2 * 0.0 = 0.0`. `recvSelf` then restores the real `m_P_atm` from `data(9)` (`:674`) but **never re-runs `initialize()`**, and there is no slot to restore `m_Presidual` from even if it did. `m_Presidual` is read at ~30 mean-stress evaluation sites throughout the integrator (`p = one3*GetTrace(stress) + m_Presidual`), including the one feeding `GetPSI()`, so the drift reaches the state parameter ψ and through it `M^b`, `M^d`, and dilatancy -- not just the stress return.
- **Workaround/status (2026-08-26, ADR-86 PR-1 -- fixed for the LadrunoSANISAND subclass only, vanilla left as-is):** `LadrunoSANISAND` overrides `sendSelf`/`recvSelf` to append one extra `Vector(4)` after the unchanged base `Vector(97)`, carrying `mPresidualInput`/`mPminInput`/`mHonorTolR` across the wire, so a `LadrunoSANISAND` worker or DB restore runs the SAME `p_r` as the serial process. Vanilla `ManzariDafalias` itself is deliberately not touched (D3) -- any deck still declaring `nDMaterial ManzariDafalias` (not the Ladruno subclass) carries this defect unchanged; any MP-vs-serial or restore-vs-live comparison on that class at low confinement is invalid. See [[86_ladruno_sanisand_adr]] §3, [[LEDGER_implementations]] LadrunoSANISAND row.
