### `ManzariDafalias::revertToStart()` silently restores the hardcoded low-stress constants mid-analysis
- **Bites:** any driver that calls `revertToStart()` (a manual `ops.reset()`/`wipeAnalysis`+resume idiom, or a framework that resets between load cases) on a `ManzariDafalias`-family material OUTSIDE an `ops_InitialStateAnalysis` block -- which is the common case; the guard exists specifically FOR the initial-state-analysis window, not for an ordinary mid-run reset. The material's low-stress constants silently snap back to the hardcoded vanilla values (`m_Pmin = 1.0e-4*m_P_atm`, `m_Presidual = 1.0e-2*m_P_atm`) at the moment of the reset, even if a caller (or a subclass) had deliberately set them to something else at construction.
- **Why:** `ManzariDafalias::revertToStart()` (`ManzariDafalias.cpp:465-476`) is: `if (ops_InitialStateAnalysis) { /* do nothing */ } else { this->initialize(); }` -- outside the initial-state window it calls `initialize()` **unconditionally**, and by the time any mid-analysis `revertToStart()` fires, `m_P_atm` already holds its real value, so `initialize()` recomputes the two constants from it and overwrites whatever was there. This is exactly the same defect surface as the sendSelf/recvSelf quirk above (same root cause -- every un-audited `initialize()` call site is a place the hardcoded constants can reappear), but reached through a completely different code path (analysis-driven reset, not serialization), so fixing the wire format alone does not fix this one.
- **Workaround/status (2026-08-26, ADR-86 PR-1 -- fixed for the LadrunoSANISAND subclass only):** `LadrunoSANISAND::revertToStart()` replicates the base's `ops_InitialStateAnalysis` guard verbatim but calls ITS OWN `initialize()` shadow (base `initialize()` followed by `applyLadrunoConstants()`), so a mid-analysis reset restores `p_residual`/`p_min` to what the deck asked for, not to 1.01 kPa. This is why a `LadrunoSANISAND` subclass MUST override `revertToStart` and cannot get away with merely shadowing `initialize()` -- shadowing alone would still lose to the base's own `revertToStart` calling the base's own `initialize()` internally via static binding (see the `virtual` quirk below for why `initialize()` cannot simply be made virtual instead). Vanilla `ManzariDafalias` is unchanged -- any deck using it directly still has this trap. See [[86_ladruno_sanisand_adr]] §4.4, §8 risk #1.
