### LadrunoConcrete3D: hydrostatic compression silently ELASTIC; `Gc` was not an energy; tension over-dissipated `Gf` (fixed 2026-09 — read before comparing to OOFEM)
- **Bites (pre-WP `concrete3d-oracle-diagnosis`):** (1) a hydrostatic-compression trial never yielded: the hardening return overshot `ρ<0`, the apex branch projected onto the TENSION vertex, the PR #249 gate rejected it and the wrapper fell back to the elastic predictor with only a warning (OOFEM `con2dpm3`: −21.43 vs −2.96 MPa); 4.6 % of plastic fuzz trials with a compressive mean stress were *accepted* at the tension vertex (admissible, so the gate let them through). (2) `Gc` mapped to `εfc = Gc/(fc·lch)` while the compressive driver is scaled by `βc/xs`, so the element dissipated ~20× `Gc`. (3) The tension history `κdt2 = κdt−ε0` stretched the exponential softening (+25–40 % over `Gf`; Grassl Fig. 7 at 0.2 mm/m: 2.80 vs 0.96 MPa).
- **Also (single-element tension benchmarks):** with only one top node displacement-controlled and the others load-controlled, the softening brick BIFURCATES into a non-uniform (rotating-face) mode — some GPs unload with frozen `ωt<1` and carry `(1−ωt)σ̄` of a strongly hardened effective stress (`Hp=0.5` ⇒ `σ̄` ~ 30× ft), so the curve never reaches zero and "dissipates" ~190 N/m for Gf = 120 regardless of `Df`. Tie the loaded face (`equalDOF` on uz) for a material-point test: it then dissipates Gf exactly. And `ωt = 1` exactly (bilinear) made the tangent singular ⇒ residual tangent stiffness `(1−ω) ≥ 1e-6` (2026-09).
- **Workaround/status:** dedicated vertex return; `-tensionLaw bilinear` (CDPM2 Eq.58) default; `Gc` calibrated as a physical energy by default (`-epsFc` = raw CDPM2 `εfc`). OOFEM's regression values are themselves ONE coarse step (5e-4): converged CDPM2 differs by up to 25 % (uniaxial compression step 5), so compare fork-vs-OOFEM at the SAME step size. Still open: compressive drive `−σ̄min/fc` erases confinement strength at damage onset (ADR-31 §11-4b). See [[31_ladruno_concrete3d_adr]] §11.

#### Follow-up (WP-867, rebased for apeGmsh #2621 phase 2a)
- **B3 (2026-09):** defaults changed to CDPM2's `Df = 0.85`, `Hp = 0.01` (were 1.0 / 0.5: Kupfer peak at −1.70 instead of −2.19 mm/m). Old models: add `-Df 1.0 -hardening 0.3 0.5`. NB even with `Hp = 0.01` the effective tensile stress keeps hardening after full cracking (κp ~ 10³ because xh ≈ Dh = 1e-6 in tension; ~20·ft at 5e-3 strain) — CDPM2 by design (OOFEM identical); harmless for the nominal stress (ω ≤ 1−1e-6).
- **PV20 (2026-09, ADR-31 §15): the hardened crack is NOT harmless for the orthogonal strut.** Literal CDPM2 Eq.47/48 has two cross-couplings. It feeds `κdc1` with `α_c·β_c·‖Δε_p‖`, which includes the crack-opening plastic strain. It feeds `κdc` with `α_c·Δε̃`, where ε̃ carries the hardened crack stress (qh2 ≈ 3). So an RC panel in shear (Vecchio–Collins PV20, ASDShellQ4 + LayeredShell) softened its strut at 0.19 fc: τ went 1.76 → 0.03 MPa against 4.26 in the test, with the steel elastic. Crack-then-compress also gave 3.3 fc with no ω_c at all. Fix: `-tcTemper proj` (default). `-tcTemper none` gives literal CDPM2. Diagnose with a material-point replay of the element strain path. The oracle `pv20_path` reproduces the element collapse.
- **B2 (2026-09, ADR-31 §13):** the compressive damage was driven by −σ̄min vs fc, so under confinement the nominal stress dropped from fcc to fc in the FIRST damaging step. Now CDPM2's E·κdc vs ft (`-compressionDrive legacy` = old). Also ω ≤ 1 − 1e-6: an exactly stress-free fully cracked state is a spurious equilibrium root (the element Newton jumped onto it). Return-map warnings are printed only for FINAL failures (rate-limited; `-verbose`, `getResponse substeps/returnFailures`).
- **B1 (2026-09, ADR-31 §12):** the v1 flow rule was always dilatant (no compactive cap normal; uniaxial peak at −1.50 instead of −2.19 mm/m on Kupfer). The full CDPM2 potential + return sub-incrementation is now the default (`-flowPotential legacy` = the old flow, no sub-incrementation). NB Grassl Fig.9's post-peak is NOT reproducible with its stated `εfc = 1e-4` in OOFEM's CDPM2 either — it needs ~6e-4.
- **F2 (2026-10-31, apeGmsh #2621): the sub-incremented return reported the LAST piece's tangent.** With `maxSubIncr > 0` (the cdpm2 default) a failed direct return is integrated in N pieces, but `returnMapTensor` returned the last piece's one-piece consistent tangent: O(1) wrong once N >= 2 (record-dump replay of the corbel: effective-layer error p50 0.45 at 2 pieces, 1.0 at >= 5). The plane-stress eps22 Newton divided by that D22. Now the chain rule over the pieces (Perez-Foguet et al. 2001): `J_k = A_k (J_{k-1} + f_k C) + b_k (x) K_{k-1}`, `K_k = a_k . (J_{k-1} + f_k C) + e_k K_{k-1}`, with `A, b, a, e` = d sig/d sig_tr, d sig/d kp_n, d kp/d sig_tr, d kp/d kp_n of each converged piece (`pieceJacobian`, the 4x4 IFT with the extra kp_n right-hand side). A direct return keeps its tangent bit for bit; `returnMapTensorSchedule` integrates a given schedule. **Verify against a FROZEN-schedule FD**: the as-is map changes its piece count inside an FD stencil in ~95 % of the sub-incremented records, so a plain FD of `returnMapTensor` is not a derivative there.
- **F2: `damagedTangent` no longer runs the return map.** Its `beta_c`, ctTemper-proj and tcTemper-proj gradients were composite micro-FDs THROUGH `returnMapTensor` (89 % of all return-map calls in a corbel run, across piece-count changes); they are closed forms now (`beta_c` via `d kp/dε` from the chain rule, the proj weights via `compressiveDamageWeightGrad`/`tensileDamageWeightGrad`: tr(S M S M) with S an isotropic tensor function). `returnMapTensor` is declared after `damagedTangent`, so a call back is a compile error; the self-check's call counter holds 0. Also fixed: a bilinear (or CDPM2-drive) omega exactly AT the `OMEGA_MAX` cap fell through to the legacy exponential IFT branch (O(1) wrong tangent on fully open cracks); the cap is flat, d omega = 0.
