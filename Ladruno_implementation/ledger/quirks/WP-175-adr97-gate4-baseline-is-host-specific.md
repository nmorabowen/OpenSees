### ADR-97 gate-4 `test_gate4_backward_euler_is_byte_identical_*` fails on Windows with no source change — the baseline's bits belong to the dumping HOST (WP-175)
- **Bites:** on the current desktop, `tests/test_adr97_p4_inertness.py` failed 3 cases: 14 of 23 decks, 357 of 1692 stress components, up to 2.0e-09 relative. That is `tet/hb` 8.130e-03 absolute on a 4.07e6 scale, VM 5.772e-09 and DP 2.033e-20, the same numbers GCC/Linux gives. All `analyze()` codes and step counts were unchanged. Every build from 2026-09-26 to 2026-10-06 failed the same way, so it looked like a regression in `Backward_Euler` (ADR-97 D1). Windows has no CI tier (WP-143), so nothing caught it.
- **Why:** the baseline was dumped on another Windows workstation. Commits through 2026-09-18 carry a `-0500` committer offset; from 2026-09-23 on they carry this desktop's `-0300`. Rebuilt **here**, the baseline's own source `3622d6214` missed its own baseline in exactly the same decks. On this host, the `3622d6214` build equals the `7e93e4381` build bit for bit, except the deliberate wp/97e entry. `7e93e4381` equals the 2026-10-06 `ladruno` on all 23 decks. So D1 holds, and the different bits come from the other machine's CPU or compiler build. This host: AMD Ryzen AI 7 PRO 350, MSVC 14.44.35207, SDK 10.0.26100.0, eigen/3.4.0 conan rev `e7256a46`. Measured to have no effect: the 2026-09-21 `ucrtbase.dll` update (`opensees.pyd` imports no UCRT; the CRT is static) and MKL (output unchanged under `MKL_CBWR=COMPATIBLE/AVX2/SSE4_2` and `MKL_NUM_THREADS=1`). Rebuilding old commits only *looks* like a commit bisect: each one picks up the current host.
- **Workaround/status:** on a new host, rebuild the baseline's own commit there before suspecting the code. If that build misses too, re-dump with the original provenance and say so in the commit. WP-175 did this: 18 decks from `3622d6214`; the wp/97e entry and the four `experimental 1` explicit-integrator decks from `7e93e4381`. The Linux 1e-6 relative floor is unaffected (worst move 2.0e-09). Related trap: `dump_hist.py` children run without `-S`, so a boot `.pth` that imports `opensees` beats `PYTHONPATH`. Check the recorded `ladrunoBuild`.

#### Follow-up (WP-177)
The owner develops on several Windows machines, so the single baseline failed on every machine but one (#960). Each host now has its own baseline: `baselines/hosts.json` maps `hostkey.host_key()` (platform + CPU brand) to that host's file, and the gate is `==` only on a registered host. Every other host, Linux included, compares against the reference file at a 1e-8 relative floor: 5x the measured 2.0e-09 host noise and 100x tighter than the old 1e-6. `test_gate4_this_host_has_its_own_baseline` SKIPs with the registration recipe (README "Adding a host"), so a machine running the weaker leg is visible in the summary. `dump_hist.child()` records `host` in every record.
