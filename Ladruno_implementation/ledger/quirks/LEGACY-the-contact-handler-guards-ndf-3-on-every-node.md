### The contact handler guards `ndf == 3` on every node of a pair -- so the whole contact engine is UNAVAILABLE on u-p nodes, and any "contact + LadrunoUP" plan is blocked until that is lifted
- **Bites:** any plan that puts a frictional/separating interface into a poromechanics model -- footing-on-saturated-soil with uplift, a retaining structure with a drained interface, TIMg-UP calibration needing a real interface, or the ADR-86 Track T P5 leg. Also anyone reading the contact ADRs (39/41/47/57/85) and the u-p ADRs (71/73/78) side by side and assuming the two subsystems compose because both are "shipped".
- **Why:** `LadrunoContactFE.cpp` builds its `myID` on the assumption that every node in the pair carries exactly three translational DOFs -- ":100-102" (`SEGMENT` mode: "fills myID = [slave xyz | seg_1 xyz | ... | seg_nps xyz] (each node ndf==3 ...) ... The handler guards ndf==3 on every node of the pair") and ":164" (`MORTAR` mode: "Every node is ndf==3 (the handler guards it) => exact ndof match"). A 3D u-p node carries ndf = 4 (ux, uy, uz, p) -- upstream `SSPbrickUP`/`BrickUP` and the fork's own `LadrunoUP` alike -- so the guard refuses the pair. The guard is correct as written (a wrong `myID` layout would silently assemble contact stiffness into the pressure row, which is far worse than a refusal); it is the DOF-mapping generalisation behind it that does not exist yet.
- **Workaround/status (2026-08-23, ADR-86 §6.4/§8 -- DISCLOSED, not fixed):** for **drained** problems, do not use a u-p element at all -- a single-phase effective-stress model (`LadrunoBrick -formulation bbar` + an effective-stress `nDMaterial`) is ndf = 3 throughout and the contact engine applies immediately. This is the recommended route for TIM/TIM-G calibration, which is drained by construction. For genuinely coupled problems needing an interface, lifting the guard means teaching `LadrunoContactFE` to map only the translational DOFs of a heterogeneous-ndf node set -- tractable (the Domain already runs mixed ndf; see ADR-71 P3's Taylor-Hood vertex-p work) but its own ADR with its own gates, NOT a one-line relaxation.
