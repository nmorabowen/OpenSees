### `ManzariDafalias`'s substep loops interpolate the void ratio FROM THE WRONG END — and `PM4Sand` in the same folder proves it is a typo, not a modelling choice
- **Bites:** inside `ModifiedEuler`, `RungeKutta4` and `RungeKutta45`, the substep pseudo-time `T` sweeps 0 -> 1 across the strain increment, so the void ratio at `T` must be evaluated at `CurStrain + T*(NextStrain - CurStrain)`. All three evaluated at **`NextStrain` + T*(...)** — a full increment ahead at `T=0`, overshooting by one at `T=1`. Void ratio -> psi -> `M^b`, so it displaces the bounding surface.
- **Why it is unambiguous:** `PM4Sand::ModifiedEuler` and `PM4Silt::ModifiedEuler` (same folder, same UW lineage) use the **same** `tmp0` accumulate idiom in the **same** loop and both start from `CurStrain`. In every one of these files the code faithfully implements its own commented-out reference line — and Manzari's comment says `NextStrain` while PM4Sand's says `CurStrain`. So the error is in Manzari's original expression; the later optimisation pass preserved a typo rather than introducing one.
- **Blast radius, MEASURED (ADR-86 PR-2):** only `ModifiedEuler` actually moves results — committed stress by 2.8e-6 relative on a normal-confinement deck, and the `M^b` departure at `p0 = 1.01 kPa` from +18.1297 % to +18.1258 %. **`RungeKutta4` does not move; `RungeKutta45` DOES.** The original claim that both were inert was REFUTED by an adversarial pre-merge review and independently re-verified: RK4's loop reads a separate `CurVoidRatio` (7 in-loop reads, 0 of `NextVoidRatio`), so there the bad interpolant only corrupted the RETURNED void ratio -- but **RK45's loop reads `NextVoidRatio` at all 11 in-loop `GetStateDependent`/`GetElasticModuli` sites and `CurVoidRatio` at none**, so RK45 is a genuine behaviour change. Measured by A/B rebuild on a NON-isochoric drained triaxial: scheme 1 and scheme 3 bit-identical, **scheme 45 reldiff 6.33e-3** (sigma_zz -1204.82 vs -1209.38 kPa). PR-2's own measurement reported zero because the confine-first test deck's deviator leg is **exactly isochoric** (trace(d_eps) = 0) and the two interpolant anchors differ by exactly trace(d_eps) -- true on that deck, falsely generalised. A defect can be real, present at three sites, and load-bearing at exactly one.
- **Status:** fixed at all three sites in one commit, ADR-86 PR-2. `SAniSandMS::RungeKutta4:1550` carries the identical error and is deliberately left for that material's own PR. `NTUASand02` is not in this tree.
- **Learned:** 2026-08-27.
