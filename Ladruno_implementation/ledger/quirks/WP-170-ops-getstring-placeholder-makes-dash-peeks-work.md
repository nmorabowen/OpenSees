### `OPS_GetString()` on a typed openseespy number returns `"Invalid String Input!"`, not null — a `peek[0] != '-'` test passes by accident, and warnings print the placeholder (WP-170, 2026-10-06)
- **What it is:** `PythonModule::getString()` returns `0` for a non-`str` arg, but **advances the cursor first**; the `OPS_GetString` wrapper (`SRC/interpreter/OpenSeesCommands.cpp:1209`) then maps the `0` to the literal `"Invalid String Input!"`. So under openseespy a peek `OPS_GetString(); OPS_ResetCurrentInputArg(-1);` on a number neither crashes nor desynchronises the cursor — and the placeholder's first letter is `I`, so "is the next token a flag?" (`peek[0] == '-'`) answers *no*, which is the right answer for a number.
- **Where it bit:** `OPS_LadrunoLoadControl` peeked its optional `numIter minLambda maxLambda` triple this way. It was reported as a crash (null `strcmp`) for `integrator('LadrunoLoadControl', 0.1, 4, 0.01, 0.1, '-tangentPredictor')`; measured on a 2026-10-02 build, **that call parses correctly** (two steps reach t = 0.15, the adaptive-increment answer, same as stock `LoadControl`). The real, visible defect was cosmetic: a stray number among the flags warned `unknown option 'Invalid String Input!' ignored` instead of naming the value.
- **The rule:** don't lean on the placeholder's spelling. Read any slot that may be a number with `OPS_GetStringFromAll(buf, len)` (it stringifies ints/floats; see the LEGACY "openseespy parsers must peek a maybe-numeric arg" quirk and WP-103's buffer-contract fix), and decide "is this positional" by **does it parse as a number** (`strtod` consumes the whole token), not by its first character — a negative positional also starts with `-`. Null-check the return: classic Tcl's `OPS_GetStringFromAll` returns `0` past the end.
- **Classic Tcl had the mirror-image bug:** everything is a string there, so a NEGATIVE value starts with `-` and was taken for a flag. `CentralDifferenceSMS 0.1 -recompute -1` warned `unknown option -1`; `ExplicitBathe 0.54 -lnvd -0.5` un-read the value, warned, and ran with the **default alpha 0.8** instead of refusing the out-of-range one.
- **Fixed in (WP-170):** `LadrunoLoadControl.cpp` (triple peek + flag loop), `CentralDifferenceSMS.cpp`, `CentralDifferenceSMSConsistent.cpp`, `ExplicitBathe.cpp` (`-recompute N` downgrade peek in every SMS variant, `-lnvd [alpha]` peek, and every flag/`-lump` token read). Each file has a local `<pfx>Tok(buf,len)` (`OPS_GetStringFromAll`, never null, force-terminated -- openseespy's `strncpy` leaves an over-long token unterminated) and `<pfx>IsNumber(tok)`. `-recompute` now consumes its token only if it is a number (a word is no longer silently swallowed); `-lnvd` treats the token as a flag only if it starts with `-` AND is not a number, so `-lnvd abc` still refuses.
- **Gate:** `tests/test_wp170_typed_arg_peeks.py` (48 cases incl. two classic-Tcl decks through `dist/bin/OpenSees.exe`). Each test is tagged `[already worked]` or `[failed pre-fix]`; on the 2026-10-02 build exactly the 18 `[failed pre-fix]` cases fail.
- **Not converted (same idiom, not in WP-170's scope):** `ladrunoContactImpl` / `ladrunoContactPlaneImpl` / `ladrunoCountLeadingNumbers` in `SRC/interpreter/OpenSeesOutputCommands.cpp` (the contact `-soft` optional-value peek the old ExplicitBathe comment called "proven"), and `OPS_printA` in `OpenSeesCommands.cpp` (its comment documents relying on the placeholder). Convert the same way when touched.
- **Also learned:** (1) the `ladrunoLoadControl` query command is openseespy/TclWrapper-only -- its classic-Tcl slot in `LadrunoCommandTable.h` is `LADRUNO_NONE`. (2) `OPS_Integrator()` returns 0 when the factory returns null, so under openseespy a REFUSED integrator raises nothing and the previous one stays in force -- the ADR-76 fix covered `OPS_Algorithm` only. **Fixed by WP-171 (#927):** a refused integrator now raises under openseespy and returns `TCL_ERROR` in classic Tcl, keeping the previous integrator; the WP-170 refusal tests assert the exception.
