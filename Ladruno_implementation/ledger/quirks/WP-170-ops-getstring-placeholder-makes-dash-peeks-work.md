### `OPS_GetString()` on a typed openseespy number returns `"Invalid String Input!"`, not null — a `peek[0] != '-'` test passes by accident, and warnings print the placeholder (WP-170, 2026-10-06)
- **What it is:** `PythonModule::getString()` returns `0` for a non-`str` arg, but **advances the cursor first**; the `OPS_GetString` wrapper (`SRC/interpreter/OpenSeesCommands.cpp:1209`) then maps the `0` to the literal `"Invalid String Input!"`. So under openseespy a peek `OPS_GetString(); OPS_ResetCurrentInputArg(-1);` on a number neither crashes nor desynchronises the cursor — and the placeholder's first letter is `I`, so "is the next token a flag?" (`peek[0] == '-'`) answers *no*, which is the right answer for a number.
- **Where it bit:** `OPS_LadrunoLoadControl` peeked its optional `numIter minLambda maxLambda` triple this way. It was reported as a crash (null `strcmp`) for `integrator('LadrunoLoadControl', 0.1, 4, 0.01, 0.1, '-tangentPredictor')`; measured on a 2026-10-02 build, **that call parses correctly** (two steps reach t = 0.15, the adaptive-increment answer, same as stock `LoadControl`). The real, visible defect was cosmetic: a stray number among the flags warned `unknown option 'Invalid String Input!' ignored` instead of naming the value.
- **The rule:** don't lean on the placeholder's spelling. Read any slot that may be a number with `OPS_GetStringFromAll(buf, len)` (it stringifies ints/floats; see the LEGACY "openseespy parsers must peek a maybe-numeric arg" quirk and WP-103's buffer-contract fix), and decide "is this positional" by **does it parse as a number** (`strtod` consumes the whole token), not by its first character — a negative positional also starts with `-`. Null-check the return: classic Tcl's `OPS_GetStringFromAll` returns `0` past the end.
- **Fixed in:** `SRC/analysis/integrator/LadrunoLoadControl.cpp` (WP-170). Gate: `tests/test_wp170_loadcontrol_typed_args.py` (openseespy triple × each flag, flag-without-triple, stray-number warning, classic-Tcl parity via `dist/bin/OpenSees.exe`). Only the stray-number case failed on the pre-fix build.
- **Same reliance, still in place (working, documented in their comments):** the `-sms ... N` optional-count peeks in `CentralDifferenceSMS.cpp`, `CentralDifferenceSMSConsistent.cpp` and `ExplicitBathe.cpp` (and `ExplicitBathe -lnvd [alpha]`). They comment that a number reads "as garbage text, but never as something starting with '-'". Convert them the same way if any is touched; a quirk-lint rule would need these three as a ratchet.
- **Also learned:** the `ladrunoLoadControl` query command is openseespy/TclWrapper-only — its classic-Tcl slot in `LadrunoCommandTable.h` is `LADRUNO_NONE`, so `OpenSees.exe` decks cannot read back `tangentPredictor`/`extrapolate`.
