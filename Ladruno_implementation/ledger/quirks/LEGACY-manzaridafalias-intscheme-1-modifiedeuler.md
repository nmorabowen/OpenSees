### `ManzariDafalias` IntScheme 1 (ModifiedEuler) IGNORES the `TolR` you passed — its substep error tolerance is hardcoded at `1e-4`
- **Bites:** every deck that tightens the optional 5th argument `TolR` on `nDMaterial ManzariDafalias ... 1 $TanType $JacoType $TolF $TolR` (or `ManzariDafalias3D`/`PlaneStrain`/`RO`/`LadrunoSANISAND`) expecting more accurate substepping. IntScheme 1 is the scheme this fork's own constructor warning *recommends* (over the uncontrolled schemes 3 and 5), so it is the scheme a careful user lands on — and it is the one that throws the request away. Nothing warns; the run converges and reports success at whatever accuracy `1e-4` buys. The tell is that halving `TolR` changes **nothing at all** in the output on scheme 1, while it does change scheme 45.
- **Why:** `ManzariDafalias::ModifiedEuler()` opens with `double T = 0.0, dT = 1.0, dT_min = 1e-6 , TolE = 1e-4;` — a bare literal. `TolE` is what the adaptive substep loop actually tests (`if (curStepError > TolE)`, and the step-size update `q = fmax(0.8*sqrt(TolE/curStepError), 0.1)`), so `mTolR` — which *is* stored, from the parser and from `data(20)` on the wire (`:618`, `:700`) — is simply never read by this integrator. It is not a family-wide convention: the sibling `RungeKutta45()` in the SAME file uses `double T = 0.0, dT = 1.0, dT_min = 1e-3 , TolE = mTolR;`, and `SAniSandMS.cpp:1484` does the same. `mTolR` *is* read elsewhere in `ManzariDafalias` — it is the Newton residual tolerance for the implicit schemes — so grepping for `mTolR` and finding hits does not tell you IntScheme 1 honours it.
- **Workaround/status (2026-08-26, ADR-86 PR-2 commit 1 — seam opened in vanilla, deliberately not wired):** the literal is now `TolE = mHonorTolRInME ? mTolR : 1e-4`, with `bool mHonorTolRInME` a protected base member initialised `false` in all four `ManzariDafalias` constructors, so **vanilla is bit-identical** (a false condition selects the `1e-4` operand verbatim — no arithmetic). A derived class opts in from its own constructor; `LadrunoSANISAND`'s `-honorTolR` deck flag is what will do so. Until a deck sets it, IntScheme 1 still runs at `1e-4` and the quirk above is live for every existing deck. **Do not "fix" this by making the integrators `virtual`** — see the `ManzariDafaliasRO` shadow quirk above; the flag seam exists precisely because `ModifiedEuler()` is non-virtual and binds statically inside the base TU.
- **Note on the two similar names:** `mHonorTolRInME` (base, `bool`, the seam) and `LadrunoSANISAND::mHonorTolR` (subclass, `int`, the deck-level request) are different members on purpose. Grepping for `mHonorTolR` hits both; the `InME` suffix means "in ModifiedEuler".
- **Learned:** 2026-08-26, ADR-86 PR-2 (audit of `ManzariDafalias` against `SAniSandMS`). See [[86_ladruno_sanisand_adr]] §4.1, D7.
