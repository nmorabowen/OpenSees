### LadrunoConcrete3D: the deterministic sub-incrementation is DISCONTINUOUS (n boundaries, ladder switches) and its tangent is the CHAIN's, not the last piece's (WP concrete3d-hang-diagnosis, [#877](https://github.com/nmorabowen/OpenSees/pull/877))
- **Bites:** `-subIncr deterministic` (the default) integrates every plastic trial in `n = ceil(f_tr/0.3)` pieces. A chain of `n` and one of `n + 1` pieces (or two ladder levels) are two different, each consistent, integrations of the same increment: `sigma_eff` jumps 0.06-0.40 MPa on 15-41 MPa (0.4-1.5 %) at `n` boundaries, and in tension near first cracking the ladder switches DENSELY (review 3 of #877, MAJOR 1; fix pending): the direct tension return fails intermittently once kappa_p passes about 2, so the serving level is a coin flip on rounding (1691-2212 level flips in 4000 points at 1e-9 relative spacing, effective-stress jumps up to 0.32 MPa, 30-97 % direct-return failures in 2e-6-wide windows). Consequences: nominally identical Gauss points differ (hosting parity ~1e-3, EAS alpha ~1e-11), `F` vs `Q@F` objectivity holds only on one branch, and a finite-difference tangent reference that lets a leg straddle a boundary differentiates the jump.
- **The tangent:** the chain is differentiated forward through the pieces with the kappa-history coupling (`PieceSens`); ignoring that coupling left 6e-2..7e-1 error at n = 2..64. Pin `n` on both FD legs (`Params::subIncrForceN`, `returnMapPieces()`, oracle `subincr_force_n`).
- **Workaround/status:** documented, tests derive tolerances from the measured jump; the root cause (the direct tension return leaves the admissible set, Kernel.h `returnMapHardening` / `newtonGlob`) is not fixed. Do not make `refuse` the default or the last piece's tangent the default until it is. `substeps` counts forced chains too.
