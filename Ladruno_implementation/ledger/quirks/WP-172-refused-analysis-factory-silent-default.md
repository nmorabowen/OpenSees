### A refused `system` / `numberer` / `constraints` / `test` raised nothing in openseespy and the next `analysis` silently built a DEFAULT; classic Tcl `system <unknown>` returned TCL_OK (WP-172, 2026-10-06)
- **Same shape as ADR-76 (`OPS_Algorithm`) and WP-171 (`OPS_Integrator` / `specifyIntegrator`)**, audited for the remaining analysis-setup factory commands. The rule: a dispatcher whose factory can return null must (a) fail with an error code the interpreter turns into an exception / `TCL_ERROR`, and (b) leave the previous object in place.
- **openseespy:** `OPS_System`, `OPS_Numberer`, `OPS_ConstraintHandler`, `OPS_CTest` called `cmds->setX(factory())` and returned `0` whatever the factory returned; `Py_ops_*` raise only on `< 0`. Worse than the algorithm case: `setSOE` / `setNumberer` / `setCTest` / `setHandler` **null the global** on a null argument (and delete the previous object when no analysis exists), so the refusal was followed by a silent default at the next `analysis` (`ProfileSPD`, `RCM`, `Plain`, and for `test` a **warning-free** `NormUnbalance 1e-6 25`). Refusing args that reach this: `system PFEM -<unknown>`, `system Mumps -ICNTL14` (no value), `numberer ParallelRCM|ParallelPlain|LadrunoParallel*` in a serial build, `constraints Penalty` / `Lagrange <bad>` / `Auto -autoPenalty`, `test <any> ` with missing tol/iter. `OPS_Analysis` returned `0` for an unknown analysis type.
- **classic Tcl:** `specifyCTest`, `specifyNumberer` and `specifyAnalysis` were already correct (local temporaries; `TCL_ERROR` before any global is touched). `specifySOE` was not: its final `if (theSOE != 0) return TCL_OK` reads the *global*, so once any system had been set, an unknown type (the package-lookup `else` branch) returned `TCL_OK` with no message. `specifyConstraintHandler`'s `Auto` / `LadrunoProjection` / `LadrunoContact` branches assigned the factory result to the global before the null check, so a refused handler was a `TCL_ERROR` that had already discarded the previous handler (visible under `catch`).
- **Not changed (recorded):** `constraints <X>` after an analysis exists is a warning-only no-op in openseespy (`can't set handler after analysis is created`) and silently not pushed into the analysis in classic Tcl — an upstream design choice, not a null-factory defect. `eigen <unknown-option> N` warns `eigen - unknown option specified` and proceeds with the default solver in openseespy — an option parser, not a factory.
- **Fix + gate:** see `ledger/vanilla/WP-172-*`; `tests/test_wp172_refused_analysis_factories.py` (openseespy refusals with/without an analysis + unknown analysis type; classic-Tcl decks via `dist/bin/OpenSees.exe`).
