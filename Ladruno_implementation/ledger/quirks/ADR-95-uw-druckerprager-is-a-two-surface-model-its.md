### UW `DruckerPrager` is a TWO-SURFACE model, its tension cutoff sits at `I1 ~ 0` for a small apex regulariser, and until ADR-95 P4 its cutoff and corner branches were DEAD CODE with a wrong tangent
- **Bites:** you calibrate `nDMaterial DruckerPrager` as "a Drucker-Prager cone with a tiny cohesion `SY` to regularise the apex", and reason about the model as if the cone were the only yield surface. It is not. The material carries a second surface — a **tension cutoff** `f2 = I1 - T` with
  `mTo = sqrt(2/3) * sigma_y / rho` (`DruckerPrager.cpp`, full constructor) — and at the ADR-95 / TIMs deck's `SY = 0.2 kPa`, `phi_txc = 20 deg` that puts `T = 1.099 kPa`, i.e. **essentially at zero mean stress**. Every Gauss point that heaves into tension (the ground surface beside a footing edge, the whole free surface of a strip-footing deck) therefore changes CONSTITUTIVE OPERATOR, not just state — `mCep` is assembled from a different `b1`/`b2`/`g_contra` in the `f2` and corner arms. Nothing warns you; the recorder `state` response does not name the branch. Note the cone apex sits at `I1 = T` too, so a point that crosses the cutoff crosses the cone in the same instant: pure tension gives the **corner** (branch 3), never `f2` alone.
- **Second bite, worse:** the multisurface residual assembly reads `if (Jact(i) == 1) {R(0)...} else if (Jact(i) == 2) {R(1)...}`, but `Jact` only ever holds **0 or 1** — the `== 2` arm is dead code. So `R(1)` is never assembled, `g` stays lower-triangular with `g(1,1) = 1`, and `gamma(1)` (the cutoff multiplier) is **exactly zero on every branch, corner included**. With `rho_bar = 0` the update `I1 -= 9K*rho_bar*gamma(0) + 9K*gamma(1)` is then identically zero: the cutoff **selects a different tangent but returns no stress**, so `I1` stays wherever the trial state left it, arbitrarily far above `T`. Measured on a single `LadrunoBrick` at uniform triaxial tension: branch 3, `gamma1 = 0.0`, `I1 = 15.000` against `T = 1.099`. Pinned as a sentinel by `tests/test_adr95_dp_branch_response.py::test_tension_cutoff_multiplier_now_returns_stress` — if that test ever fails someone has repaired the cutoff, and any ADR-95 conclusion resting on H1 has to be re-derived.
- **Third bite:** at *exact* hydrostatic tension with `rho_bar = 0`, `norm_eta` is 0 both before and after the return map, `n` is zeroed, and the tangent's last term `- 4G^2/norm_eta * gamma(0) * (IIdev - n(x)n)` divides by zero — `mCep` comes back non-finite, and `NormCep < 1e-10` does not catch it. Any probe that drives this material to a perfectly hydrostatic tensile state must perturb the deviator.
- **`Jact = ` / `count = ` on stderr means the forced-accept fired.** `plastic_integrator` prints those two lines only from the `count > 3` bailout, which abandons the Kuhn-Tucker search, forces `Jact = (1,1)` and accepts the corner. Their **absence** in a log is evidence the bailout did NOT fire — which is how ADR-95 excluded that path as the trigger for the quadratic wall before instrumenting anything.
- **How to see any of it:** `eleResponse(tag, 'material', gp, 'ladrunoBranch')` (ADR-95 P0, PR #803) returns `[branch, gamma0, gamma1, f1_trial, f2_trial, forcedAccept, I1, detAmin]`; `branch` is `Jact(0) + 2*Jact(1)` read AFTER the whole `while(!okay)` loop, and `detAmin` is `min_n det(n.D_ep.n)/(2G)^3`.
- **Fourth bite, measured at P0 and load-bearing for ADR-95 H2:** with `rho_bar = 0` (fully non-associated) and perfect plasticity (`H = theta = 0`), `detAmin` goes **negative the instant a Gauss point yields on the cone** — a single `LadrunoBrick` under uniform compression + shear reads `detAmin = -7.5e-3` at first yield, against the exact elastic value `(K + 4G/3)/(8G) = 0.4792`. Loss of ellipticity in this material is therefore the GENERIC state of any plastic Gauss point, not a rare event, so "`detAmin < 0` appeared" is worthless as a discriminator; only the **fraction / spatial connectivity** of negative-`detAmin` points can be compared across elements.
- **Date:** 2026-09-07 (ADR-95 P0). Cross-links: `Ladruno_implementation/95_prandtl_reissner_quadratic_root_cause_plan.md` §2 (H1), [[LEDGER_vanilla_files]] rows for `DruckerPrager.{h,cpp}`.
- **FIXED in ADR-95 P4 (PR #803) -- and this is the headline: any non-associated DP leg that reaches `I1 >= T` on a PRE-FIX build dies in Newton with a ~1000x drop in the smallest singular value of the global operator.** The second and third bites above were one defect, and it had a fourth face nobody had looked at: because `g(1,1)` stayed at the dummy `1`, the INVERSE `g_contra` used to build the consistent tangent was dimensionally wrong (`g_contra(1,1) = +1` where it should be `-1/(9K)`), so the corner tangent picked up two spurious rank-one terms in stress-squared units -- `+9K^2 * 1(x)1` and `-27*rho*K^2 * n(x)1` -- scaling as `9K^2/(2G)` and `27*rho*K^2/(2G)` relative to `2G`. That is the 5-8 decade `detAmin` outlier ADR-95 P1 measured at the first four Gauss points to cross the cutoff (`-3e5 ... -6.6e7` against `-0.06` everywhere else), and it enters the GLOBAL operator, which is why the symptom is a global Newton seizure and not a local material warning. P4 makes the assembly index-driven (`if (Jact(0)==1) {row 0} if (Jact(1)==1) {row 1}` -- the row index is the SURFACE index, not the loop counter) and fixes the one genuinely wrong factor in the tangent block: the radial-return softening term must divide by `||eta_TRIAL||`, where upstream divides by the norm of the RETURNED eta that it has just recomputed for `mState(1)`. **Upstream master still carries both** (checked 2026-09-07: dead `Jact(i)==2` arms at lines 495 and 530, the final-norm divide at line 670), as does the fork's own sibling `SRC/material/nD/DruckerPragerThermal.cpp` (lines 751, 787) -- so treat ANY other copy of this return map as defective until checked.
- **Two consequences that look like new bugs but are correct answers.** (a) `mTo` is not a free parameter: the constructor sets `T = sqrt(2/3)*sigma_y/rho`, which is exactly the cone apex, so on a NON-hardening deck `f1 = f2 = 0` forces `||eta|| = 0` -- every corner return lands on the apex, the stress is pinned at `sigma = (T/3)*1`, and the exact consistent tangent is **zero**. The pre-existing `NormCep < 1e-10` floor catches that and hands the solver `1e-3*Ce`; P4 throttles its `NormCep = ...` message to 10 lines because it now fires at every apex GP. (b) The **f2-only branch is algebraically unreachable** without hardening (`f1 <= 0 < f2` would need `||eta|| < 0`), which is why P1 never saw branch 2 and why a test for it needs `theta = 1, H > 3G`.
- **The third bite (hydrostatic NaN) is fixed too**, by guarding the softening coefficient with the same `> 1e-13` test the code already applies to `n`; a probe no longer has to perturb the deviator.
