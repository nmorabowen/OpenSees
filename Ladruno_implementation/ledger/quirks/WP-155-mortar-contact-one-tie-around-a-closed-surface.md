### Mortar contact: one tie around a CLOSED surface silently binds the far side; a per-commit Uzawa makes a LINEAR tie step-count dependent (WP-155, 2026-09-29)
- **Bites:** (1) the mortar broad phase is brute force and the kernel clip accepts anti-parallel facets (`|cos|`), so on a closed skin (a pile) each facet is also tied to the ANTIPODAL facets — R1 measured one cylinder tie 3.65× too stiff, with no warning. (2) the shipped default augments λ once per `Domain::commit()`, so even a linear penalty tie gives a different answer for 1 vs 2 vs 5 load steps (exactly the 1-D Uzawa recursion: 2.2e-3 / 2.1e-3 / 2.04e-3 on the split column).
- **Also:** a `-adjust`ed node sits at p = 0 EXACTLY, which the shipped `pr < 0` mask treats as open — the first iterate then has no interface stiffness (a floating pile). WP-155 takes the closed tangent branch there. And a frictionless contact on a near-circular interface has NO torsional stiffness: a test slice must pin the rigid rotation or Newton chatters.
- **Also:** the `-augment` gate must cover EVERY Uzawa in `commit()`: the ADR-57 E6 edge-edge λ_N was missed at first (review #897 finding 1).
- **Status:** `-maxGap d` (pairing guard), `-augment request|never`, `-adjust`/`-gapOffset` — [[155_pile_contact_r05]]. Defaults unchanged.

#### Follow-up (WP-99, 2026-10-30): a default guard for `-tie`, and the same hole in `LadrunoTie -mortar` (r6 backport)
- **Mortar contact `-tie`:** with no `-maxGap`, a pair is tied only if it overlaps in the REFERENCE configuration and its reference mean |gap| over that overlap is at most `0.5*sqrt(A_s)` (A_s = slave facet area); exclusions are reported once per contact (`WARN_TIE_EXCLUDED`). `-maxGap` still replaces it (old behaviour under `-maxGap`). Both halves are needed: with the gap test alone the closed cylinder was still 1.3e-3 off the sector split (pairs that do not overlap as built). `test_n1_maxgap_closed_cylinder_tie_matches_sector_split` now pins default == split to 1e-6 (the old assertion pinned the over-stiff default) and `-maxGap 10` as the over-stiff case.
- **Coincident `-tie` (fixed in the follow-up below):** a slave facet COINCIDENT with a master facet under `-tie` with auto orientation did not bond in the fork (up/61's two-parallel-facet box deck: `-maxGap 0.5` alone is singular; `-maxGap 2` bonds once, upstream twice).

#### Follow-up (2026-10-31): a coincident or zero-gap staggered `-tie` pair was never bonded
- **Bites:** the automatic orientation is `scen - mcen`, which is 0 on a coincident pair and tangential on a zero-gap non-matching one. `LadrunoContactProjection::normalOriented` (gate H2) refuses a GP whose `|n.refDir| < 1e-12 |refDir|`, so `integratePair` integrated nothing: the default guard skipped the pair as "no overlap as built" (no message) and a `-maxGap` FE stayed inert. The near facet was never tied; `-maxGap 2` bonded only the FAR facet. The P5 orientation warning exempted ties because the bond is sign-independent, but the projection refusal is not.
- **Fix:** for a `-tie` with auto orientation, `|nM.orientDir| <= 1e-9 |orientDir|` (nM = master facet Newell normal) replaces orientDir by nM. The test is relative and 1e3 above the projection's 1e-12. up/61 has the same fallback as an EXACT `== 0.0` test, which catches the axis-aligned box but not a zero-gap staggered pair on a tilted plane (round-off ~1e-17). So up/61 SHARES the bug in that case (by inspection; up/* not changed here). Tests: `test_n1_coincident_tie_bonds_the_near_facet` (up/61's box) and `test_n1_zero_gap_staggered_tie_on_a_tilted_plane`; the closed-cylinder default still equals the sector split to 1e-6.
- **`LadrunoTie -mortar`:** the setup-time generator integrated the far side too (the clip accepts anti-parallel facets, and the guards summed the antipodal pairs into the coverage and gap measures). A pair with mean |gap| > `tolFrac*0.5*sqrt(A)` is now excluded from D and M (both passes), with one NOTE line; an offset slave is still refused, now through its uncovered area. Tube R = 0.5, 16/24 facets, rigid rotation: slave error 97 % -> 0.9 % of omega R (`test_mortar_closed_tube_follows_rigid_rotation`). Both fixes were made first on `up/58-ladruno-tie` / `up/61-ladruno-contact-mortar` for the upstream port and brought back.
