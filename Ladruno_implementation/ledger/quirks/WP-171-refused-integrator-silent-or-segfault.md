### A refused `integrator` raised nothing in openseespy (previous one silently kept) and SEGFAULTED classic Tcl when an analysis existed (WP-171, 2026-10-06)
- **openseespy:** `OPS_Integrator()` returned `0` whatever the factory returned; `Py_ops_integrator` raises only on `< 0`. A refused integrator printed its WARNING and the run carried on with the previous integrator. ADR-76 had closed this hole for `OPS_Algorithm` only. Test code written before WP-171 that "checks a refusal" must have asserted on stderr, never on an exception (e.g. `tests/test_wp170_typed_arg_peeks.py` `_integrator_stderr`).
- **classic Tcl:** almost every `specifyIntegrator` branch is `theXIntegrator = OPS_X(); if (theXAnalysis != 0) theXAnalysis->setIntegrator(*theXIntegrator);` with no null check. With an analysis present, a refused integrator dereferenced null (exit 0xC0000005 / 139). Without one, it returned `TCL_OK` with the global set to null, so the next `analysis` printed `no Integrator specified, ... default will be used`. A parse error in a Ladruno factory could therefore change the integrator to a default with only that one line to show for it.
- **General shape — check it for every factory command:** the factory may return null; the dispatcher must (a) fail with an error code the interpreter turns into an exception or `TCL_ERROR`, and (b) leave the previous object in place. `OPS_Algorithm` (ADR-76) and `OPS_Integrator`/`specifyIntegrator` (WP-171) now do. The remaining analysis-setup commands were audited in WP-172 (Follow-up below).
- **Fix + gate:** see `ledger/vanilla/WP-171-*`; `tests/test_wp171_refused_integrator.py` (openseespy static + transient, with/without analysis, unknown type; classic-Tcl decks via `dist/bin/OpenSees.exe`, one of which segfaulted pre-fix).

#### Follow-up (WP-172, 2026-10-06): `system` / `numberer` / `constraints` / `test` / `analysis`
- **openseespy — all four factory dispatchers had the WP-171 hole, and it was worse:** `OPS_System`, `OPS_Numberer`, `OPS_ConstraintHandler`, `OPS_CTest` called `cmds->setX(factory())` and returned `0`. `setSOE` / `setNumberer` / `setCTest` / `setHandler` NULL the global on a null argument (deleting the previous object when no analysis exists), so the refusal raised nothing and the next `analysis` silently built a default. The defaults are `ProfileSPD`, `RCM` and `PlainHandler`, and for `test` a **warning-free** `NormUnbalance 1e-6 25`. Measured refusals: `system PFEM -<unknown>`, `numberer ParallelRCM` (serial build), `constraints Penalty` (no args), `constraints Auto -autoPenalty`, `test NormUnbalance` / `test EnergyIncr 1e-8` (missing args). `OPS_Analysis` returned `0` for an unknown analysis type. Unknown types of the four commands already returned `-1`.
- **classic Tcl `system` — silent, then a use-after-free:** the stock `specifySOE` ends with `if (theSOE != 0) { analysis->setLinearSOE(*theSOE); return TCL_OK; }`, which reads the GLOBAL. Once any system had been set, a call that created nothing (`system <unknown>`, `system PFEM -<unknown>`) returned `TCL_OK`. With an analysis present it also re-installed the SAME pointer, and `StaticAnalysis::setLinearSOE` deletes the old SOE before using the new one. The next `analyze` killed `OpenSees.exe` with exit 127 and no message.
- **classic Tcl `constraints`:** the `Auto` / `LadrunoProjection` / `LadrunoContact` branches assign the factory result to the global before the null check, so a refusal was a `TCL_ERROR` that had already discarded the previous handler (under `catch`, `analysis` then used `PlainHandler`).
- **Already correct (premises in the test):** classic-Tcl `test`, `numberer` and `analysis` (local temporaries; `TCL_ERROR` before any global is touched); every unknown-type branch in openseespy.
- **Not changed (recorded):** `constraints` after an analysis exists is a warning-only no-op in openseespy and is not pushed into the analysis in classic Tcl; this is an upstream design choice, not a null factory. `eigen <unknown-option> N` warns and keeps the default solver (an option parser, not a factory). Classic-Tcl `system Mumps -ICNTL14` with no value warns and still creates a Mumps SOE by design (ADR-75 P2h), but only in the targets built with `_MUMPS`.
- **Serial `OpenSees.exe` and `opensees.pyd` are built WITHOUT `_MUMPS`** (CMake adds `MUMPS_FLAG` only to the SP, MP and openseesmp targets), so `system Mumps` there is an UNKNOWN type. Before WP-172 that meant `system FullGeneral; analysis Static; system Mumps; analyze 1` was the use-after-free above (exit 127). A deck that ran `system Mumps` in the serial exe silently solved with the previous system. Regression decks: `tests/test_wp173_unknown_system_keeps_soe.py` (WP-173).
- **Fix + gate:** see `ledger/vanilla/WP-172-*`; `tests/test_wp172_refused_analysis_factories.py`.
