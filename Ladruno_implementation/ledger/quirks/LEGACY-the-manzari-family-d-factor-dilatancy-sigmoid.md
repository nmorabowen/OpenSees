### The Manzari-family `D_factor` dilatancy sigmoid is DIMENSIONAL — a bare `7.2713` multiplying a raw stress, so the same deck is a different soil in kPa, Pa and MPa
- **Bites:** any `ManzariDafalias` / `ManzariDafalias3D` / `PlaneStrain` / `RO` / `SAniSandMS` / `LadrunoSANISAND` deck that declares `P_atm` in anything other than **kilopascals**, at low confinement. The guard reads `if (p < 0.05 * m_P_atm) D_factor = 1.0/(1.0 + exp(7.6349 - 7.2713*p));` — the *trigger* scales with the unit system, **the sigmoid inside it does not**. `7.2713` multiplies a raw stress, so it has to carry units of 1/stress, and it was calibrated in kPa. At a true confinement of 1 kPa the dilatancy factor comes out **0.410 in kPa, 1.000 in Pa (the sigmoid never fires), 0.0005 in MPa (dilatancy is annihilated)**. Three different materials from one input file, converging and reporting success in all three. OpenSees has no unit system, so nothing can catch this.
- **Why it is easy to miss:** the surrounding code is *scrupulous* about `m_P_atm` — `GetPSI` uses `(p/m_P_atm)^ksi`, `b0` uses `sqrt(p/m_P_atm)`, the trigger itself is `0.05*m_P_atm`. The one dimensional constant sits in the middle of correctly non-dimensionalised neighbours, which reads as deliberate. It also appears at **four** sites in `ManzariDafalias` — `GetStateDependent` and three byte-identical replicas in the analytical-Jacobian lane (`NewtonSol`, `NewtonSol_negP`, `GetJacobian`), each with **its own derivative** `be*temp1/pow(1+temp1,2)`. Patch the value at some sites and not others, or the value without the derivative, and the consistent Jacobian stops linearising its own residual; the symptom is a convergence defect that gets blamed on the integrator.
- **Fix and the trap inside the fix (2026-08-26, ADR-86 PR-2 commit 3 — fixed in vanilla, all four sites, D5b):** rewrite as `1/(1 + exp(a - b*p/m_P_atm))` with `a = 7.6349` unchanged and `b = 7.2713*101.0`. **Spell the product out in the source; do NOT write the rounded `734.401`** — `734.401/101 = 7.27129703`, a 4.1e-7 relative shift, so the rounded literal is *not* the no-op it looks like, while `(7.2713*101.0)/101.0 == 7.2713` bit-for-bit in IEEE double. Group it left-to-right (`7.2713 * 101.0 / m_P_atm * p`) so the constant folds, divides back exactly, and only then multiplies `p`. In the three Jacobian blocks the local `double be` **is** `d(exponent)/dp`, so redefining `be = 7.2713*101.0/m_P_atm` and routing `temp1`/`D_factor` through it rescales value and slope in one edit. Verified as an exact no-op three ways: the bit-identity above, 500 000 random `p` across the whole trigger domain with zero mismatches in value or derivative, and a 1200-step low-`p` drained triaxial returning bit-identical committed stress hex-for-hex.
- **The sibling copy is worse, and is NOT fixed:** `SAniSandMS.cpp:2627` carries the same bare constants at one site, but its trigger is `p < 0.001*m_P_atm` (0.101 kPa), not `0.05*m_P_atm`. Over that entire window the factor runs 4.8e-4 … 1.0e-3, i.e. it is not a smooth ramp at all but a ~1000x hard kill of dilatancy — constants tuned for a 5.05 kPa window applied in a 0.101 kPa one. `NTUASand02.cpp`, which ADR-86 §7.2 names as the third copy, **is not present in this tree**.
- **Open (ADR-86 D5a):** whether this sigmoid should exist at all once `m_Presidual = 0`. It and the residual pressure look like overlapping patches for the same low-`p` problem applied at different times. Non-dimensionalising the constants does not settle that.
- **Learned:** 2026-08-26, ADR-86 PR-2. See [[86_ladruno_sanisand_adr]] §7.2, §7.2.1, D5a/D5b.
