### `ManzariDafalias::debugFlag` is a `static const bool` set to `false` — all 61 of its `if (debugFlag)` diagnostics are dead code in every shipped build
- **Bites:** anyone reading `ManzariDafalias.cpp` and concluding the model is well-instrumented because the integrators are dense with `if (debugFlag) opserr << "..."` — singular-matrix reports, "stress state outside the yield surface!", "dGamma cannot be negative!", "Didn't find alpha!", and (the sharp one) the low-`p` stress-clamp notices. **None of them can ever print.** There is no runtime switch, no `-debug` flag, no `setParameter` hook: `const bool ManzariDafalias::debugFlag = false;` (`ManzariDafalias.cpp:56`, declared `static const bool` at `ManzariDafalias.h:219`), so flipping it is a source edit plus a full rebuild of every ManzariDafalias TU. The practical consequence is that when this material does something silently wrong, the code *looks* like it would have told you, and it never did.
- **Why it matters most at the clamp:** two integrator entry guards do not merely report — they **change the answer**. `ModifiedEuler()` on `p < m_Pmin + m_Presidual` and `RungeKutta45()` on `p < m_Pmin` both rebuild the returned stress as `GetDevPart(NextStress) + m_Pmin * mI1`, i.e. they preserve the deviator and *paste in* the floor pressure. Downstream the point reports a stress, converges, and is indistinguishable from a real result; the mobilised strength it carries is whatever `m_Pmin` bought. This is the observable ADR-86 §8 risk 6 and the "`-Pmin` has no behavioural gate" hole both needed.
- **Workaround/status (2026-08-26, ADR-86 PR-2 commit 2 — fixed at the two clamp sites, in vanilla):** both clamps now emit an **ungated** `opserr` naming the material tag, the offending `p` and the threshold. The rest of the `debugFlag` diagnostics are left alone. **The throttle is the whole design problem, and "once per material instance" is the wrong answer:** the clamps sit inside a `while (T < 1.0)` substep loop, inside a Gauss-point update, inside a Newton iteration, inside a load step — *and* every Gauss point is its own material instance, because `getCopy(const char*)` runs a full constructor per integration point (ADR-86 PR-1 measured 513 echo lines from a 64-element mesh, extrapolating to ~400k lines / 83 MB of stderr on a 50k-element model). What is actually bounded is a **process-wide budget**: a function-local `static int`, first 10 events print, then one suppression notice, then silence — 11 lines per site regardless of mesh size. Use this pattern for any new diagnostic anywhere inside a material update; per-instance latching is not a throttle in OpenSees.
- **Learned:** 2026-08-26, ADR-86 PR-2. See [[86_ladruno_sanisand_adr]] §6, §8 risk 6.
