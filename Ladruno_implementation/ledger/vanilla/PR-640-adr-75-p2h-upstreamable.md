| `SRC/tcl/commands.cpp` | `// Ladruno ADR-75 P2h`: **`system Mumps` Tcl ladder — wire the P2/P2b options that existed only in Python, and stop the silent drop.** `-BLR <eps>`, `-stats`/`-mumpsStats`, `-ICNTL35 <n>`, `-CNTL7 <x>` added, and the ctor call changed from `MumpsParallelSolver(icntl7, icntl14)` to the 5-arg form on **both** parallel arms. **Why it mattered more than the P1d/P1e cases:** `OpenSeesMP` is Tcl-driven, so the cluster — *the only place MUMPS runs* — could not reach BLR at all, and the ladder's `else currentArg++` arm dropped unknown options **silently**, so `system Mumps -BLR 1e-8 -stats` produced a plain full-rank solve with no stats. That does not fail; it reads as "BLR does not move `INFOG(21)`" — a **false negative that would have been recorded as the ADR-75 item-1 measurement**. Also fixes a latent **read past the end of `argv`** (every value-taking option read `argv[currentArg+1]` with no bounds check, so a trailing `-ICNTL14` overran) and replaces the silent skip with a warning. Unknown options stay **non-fatal** (decks may carry options a given build lacks) but now leave a mark. Existing spellings byte-identical: BLR/stats default off ⇒ the 5-arg ctor reproduces the 2-arg defaults exactly. Names/defaults mirror `OpenSeesCommands.cpp` so the two ladders cannot drift. `-matrixType` was already present here and is **untouched**. **Blast radius checked, not assumed:** every `system Mumps` invocation in the tree that goes through *this* ladder (`EXAMPLES/**.tcl`, `tests/ladruno_cms_physical_smoke.tcl`) passes **no options at all**, so the new warning fires on nothing; every options-bearing caller is Python and uses the other ladder. **Residual drift, deliberately left and recorded rather than hidden:** `-commSplit` (ADR-43 P3a) is still Python-only — it is collective (`MPI_Comm_split`, every rank must call it) and has no Tcl gate, so wiring it blind was out of scope; a Tcl deck passing it now gets a warning instead of silence, which is the point. Serial and SP arms gain explicit "not supported / not honoured" warnings rather than dropping the option (checked where we *depend* on it: the serial `MumpsSolver` ctor carries no BLR/stats parameters, and the SP `MumpsParallelSOE` ctor takes no `matType`). **Verified by compiling all three `#ifdef` arms** (`_PARALLEL_INTERPRETERS`, `_PARALLEL_PROCESSING`, serial) with `cl /Zs` under the exact ninja `OpenSeesMP` defines/includes, with a negative control (injected error inside the new `-BLR` branch ⇒ FAIL at that line) proving the check is not vacuous. **NOT executed** — no Tcl+MUMPS binary was reachable this session (the cluster rebuild was deferred by the owner), so the runtime parity smoke (the `p1d_tcl_smoke.tcl` analogue) is owed at the item-1 cluster run. | ADR-75 P2h [#640](https://github.com/nmorabowen/OpenSees/pull/640) |
