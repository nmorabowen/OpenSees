| `SRC/interpreter/OpenSeesCommands.cpp` | **Upstreamable** (pure upstream usability defect). `// Ladruno`: `OPS_printA()`'s `-sparse <baseIndex>` argument is OPTIONAL -- the code guards it with `if (OPS_GetNumRemainingInputArgs() > 0)` -- but the READ was unconditional, so `printA -sparse -ret` (the natural way to ask for the sparse matrix BACK) consumed `-ret` as the base index, failed to parse it and returned -1 with `failed to read -sparse <baseIndex>`. The only working order was the non-obvious `printA -ret -sparse 0`, which makes the flags look positional when they are not. Now PEEKS with `OPS_GetString()` + `OPS_ResetCurrentInputArg(-1)` and consumes the token only when it is not an option flag. Classification rule REUSED from the contact parser's `ladrunoCountLeadingNumbers` (`OpenSeesOutputCommands.cpp`), including its caveat: a token is a FLAG only when `-` is followed by a LETTER, so a NEGATIVE NUMBER is still read as a number, and `OPS_GetString()` never returns null (it returns the literal `"Invalid String Input!"` for a non-string and at end of input) -- which is not `-`-prefixed and so counts as a number, the right answer for a numeric argument, while end-of-input cannot reach the branch because the remaining-args guard already excluded it. `-precision` has the same unconditional read but its argument is not optional in practice, so it is left alone. Found while verifying the SOE-shrink fix's sparse-export path. Gated by `tests/test_printa_unsized_soe.py::test_printa_sparse_flag_order_is_free` (all three orderings + the base-index shift; fails pre-fix on `sparse_then_ret`). | [#761](https://github.com/nmorabowen/OpenSees/pull/761) |
| `SRC/tcl/commands.cpp` | **Upstreamable.** `// Ladruno`: the CLASSIC-TCL twin of the `OPS_printA` `-sparse` fix in the row above. `SRC/tcl/commands.cpp` carries a SECOND, independent `printA` -- its own argv walk, and the one `OpenSees.exe`/`OpenSeesSP`/`OpenSeesMP` actually run -- with the identical defect, so fixing the openseespy path alone would have left the engine most `.tcl` decks use still broken and every Python gate still green. **That drift is a known failure mode on this fork, not a hypothetical**: see the [#729](https://github.com/nmorabowen/OpenSees/pull/729) row (`ladrunoArcLength`/`ladrunoDR` registered only in the Python wrappers, so a `.tcl` deck could START a dynamic relaxation but never read its settling gate) and the ADR-75 P2h row (a Tcl `system Mumps` ladder that silently DROPPED `-BLR`/`-stats`). The Tcl version was also marginally worse than the Python one: `currentArg++` ran BEFORE the bounds test, so a bare trailing `printA -sparse` (index omitted, nothing after it) survived only by luck -- the cursor landed on `argc` and the loop ended. Now peeks `argv[currentArg+1]` and consumes it only when it is not an option flag; Tcl hands every token over as a string, so the same `-`-followed-by-a-LETTER rule keeps a NEGATIVE base index readable as a number. Gated by `tests/test_printa_sparse_flag_order_tcl.py` + `tests/tcl/printa_sparse_flag_order.tcl` (4 orderings incl. the bare trailing form; the deck `catch`es each call so a refusal is a reported FAIL rather than an aborted deck, and the wrapper asserts the check COUNT so a deck that dies early cannot pass vacuously). | [#761](https://github.com/nmorabowen/OpenSees/pull/761) |
