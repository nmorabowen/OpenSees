| `SRC/domain/pattern/drm/H5DRMLoadPattern.cpp` | `// Ladruno WP-187`: `drm_direct_read` read four 3x1 hyperslabs per DRM node and step through HDF5's default 1 MiB chunk cache; a rank's stations span more gzip chunks (192 x 125 in the Paper 1 files) than fit, so nearly every read re-inflated a chunk. Now (1) `open_drm_dataset` opens the motion datasets with a dataset-access `H5Pset_chunk_cache` sized from the chunk dims and the rows this rank reads (two chunk columns, 1 MiB floor, 1 GiB ceiling, `nslots` a prime >= 100 x chunks), and (2) `ensure_block` / `block_value` read the rank's rows for a block of chunk-length + 1 time steps (one `H5Dread` per contiguous row run) and serve i1/i2 from memory. Same file bytes, unchanged interpolation (and WP-186 flip): loads bit-identical; the per-node read stays as the `-prefetch 0` / failure fallback. The per-step `H5DRM(r) : t = ...` / `CalculateBoundaryForces` lines print only with the new `-verbose` flag, which also prints a read timer when the pattern is destroyed. New trailing flags `-verbose`, `-prefetch <nsteps>`, `-chunkCacheMB <mb>` in `OPS_H5DRMLoadPattern` (taken out before the positional parse, so the argument counts and the "exactly 12 T/x0 values" test are unchanged). Synthetic Legacy-layout bench (9 000 stations, 4 900 DRM nodes, serial): read + interpolation 309 -> 6.5 ms/step. Tests: `tests/test_wp187_h5drm_block_reads.py`. | [#TBD](https://github.com/nmorabowen/OpenSees/pull/TBD) |
