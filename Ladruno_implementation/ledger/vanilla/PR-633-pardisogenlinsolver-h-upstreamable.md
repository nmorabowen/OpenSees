| `SRC/system_of_eqn/linearSOE/pardiso/PARDISOGenLinSolver.{h,cpp}` | `// Ladruno ADR-75 P1e`: **`-krylov <L>` — factorization-preconditioned CGS (`iparm[3] = 10*L+K`).** The P1 `factored` gate can only skip work when A is UNCHANGED, so it pays *nothing* under full Newton; `iparm[3]` is the complementary axis — it reuses the retained L/U as a **preconditioner** for a tangent that HAS changed. New `setKrylov(digits)` + `krylovL`/`krylovK` members; K is derived at the symbolic phase from `mtype` (1 = LU-CGS for 11, 2 = LL^T-CG for 2) and **refused with a warning for mtype −2** — Intel documents K=2 for symmetric *positive definite* only, so the symmetric-indefinite path (the right one for a softening tangent) cannot use this lever at all. Three non-obvious pieces: (1) **phase 23 is mandatory** — Intel documents the automatic direct fallback ("the factorization … is automatically recomputed in cases where the Krylov Subspace iteration failed") for phase 23 ONLY; under phase 33 the same failure is just `error=-4`. (2) **A CGS *win* leaves the stored factors one tangent behind**, so the new `factorsCurrent` flag forbids the phase-33 shortcut afterwards — without it a second solve against the same A silently answers with the PREVIOUS tangent (silent-wrong-answer, not a crash); `haveFactors` is tracked separately (is there a preconditioner at all). (3) `iparm[19]` is decoded (`-it_cgs*10 - cgs_error`), and **`cgs_error 5` is reported once even without `-stats`** — it is Intel's own "this flag is not worth it on this matrix", whose only other symptom is a run that is quietly slower. Perturbed-pivot check hoisted to `ops_pardiso_perturbed()` since the phase-23 path can also end in a factorization. Off by default ⇒ byte-identical to P1d when `-krylov` is absent. **Measured (Lane B, full Newton, 15 steps): 1 thread 1.53× @11.5k DOF / 2.03× @26.5k; 4 threads 1.24× / 1.30×** — the win is real but threading erodes it (factorization parallelizes, triangular solves do not), so the 4-thread production number is the honest headline. | [#633](https://github.com/nmorabowen/OpenSees/pull/633) |
