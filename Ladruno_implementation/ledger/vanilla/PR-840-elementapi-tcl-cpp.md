| `SRC/api/elementAPI_TCL.cpp` | `// Ladruno (WP-103)`: **`OPS_GetStringFromAll` never wrote the caller's buffer under classic Tcl.** It was a bare `return OPS_GetString();` -- a correct RETURN value (everything IS a string in Tcl) but it ignored the contract `elementAPI.h:209` documents (*"does a strcpy"*) and that the openseespy backend `PythonModule::getStringFromAll` honours. Every caller written in the family idiom `char tok[64]; OPS_GetStringFromAll(tok, sizeof(tok)); if (strcmp(tok, "auto") == 0) ...` therefore read **uninitialised stack** under `OpenSees.exe`, and the option was silently lost -- measured on the `9c2f964` release build as `WARNING LadrunoKinematicCoupling: -k wants a number or 'auto', got '<garbage>'` and `WARNING LadrunoEmbeddedNode: nHost must be >= 1 (or use -host eleTag); got '<garbage>'`. The fix copies the token in (NUL-terminated, truncated at `len-1`) and returns the buffer. **Out-of-args still returns `0`** -- exactly what `OPS_GetString()` returns in this translation unit -- so no existing null-checking caller changes behaviour (the two private shims that already worked around this bug, `upGetTok` in `OPS_LadrunoUP.cpp` and `ovGetTok` in `OPS_LadrunoPorousOverlay.cpp`, both null-check and are unaffected); the buffer is emptied so a caller that ignores the return reads `""` rather than garbage. **NOT mirrored in `SRC/runtime/parsing/InterpreterAPI.cpp`**, which carries the identical defect but is **dead code in this fork** -- `SRC/runtime` is not in `SRC/CMakeLists.txt`'s `add_subdirectory` list, so `OPS_Runtime` is never built and the fix would be unverifiable. Found by WP-101 (#839). **Gate:** `tests/test_wp103_getstringfromall_tcl.py` + `tests/tcl/wp103_getstringfromall.tcl`, which shell out to `OpenSees.exe` -- the defect is classic-Tcl-ONLY, so no Python test could ever have caught it (111/111 openseespy cases for the affected elements passed on the pre-fix build). See [[LEDGER_quirks]]. | [#840](https://github.com/nmorabowen/OpenSees/pull/840) |
