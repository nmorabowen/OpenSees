| `SRC/material/nD/UWmaterials/ManzariDafalias.cpp` | `// Ladruno`: **TIMs report safety pack, three traps.** (1, item 7) The two full constructors used by the Tcl/Python `nDMaterial ManzariDafalias` command never set the STATIC, class-wide `mElastFlag`, so it kept its file-scope default of `1` (ELASTOPLASTIC) — even though the parallel/classTag constructor already sets it to `0` and the community staged-gravity idiom (elastic gravity, then `updateMaterialStage -material N -stage 1`) assumes the material starts elastic. Without an explicit stage-0 call, "elastic" gravity ran the full plastic model from zero stress (a singular regime) and stalled Newton with **no diagnostic at all**. Fixed by adding `mElastFlag = 0;` to both full constructors, matching the parallel ctor. (2, item 8) `Elastic2Plastic()`'s "Outside Bounding!" `opserr` warning was commented out upstream, so a stage-switch stress ratio above the bounding surface silently bumps `M_c` by 10% with no trace; restored as a warning reporting the material tag, old `M_c`, and new `M_c` (numerics unchanged — upstream's behaviour is kept, only the silence is fixed). (3, item 3/4) Integration schemes 3 (`RungeKutta4`, whose adaptive branch is dead code, `if (false)`) and 5 (`ForwardEuler`) take one uncorrected substep with no error estimate and no yield-drift correction — a reported triaxial characterisation came out 31-46% too strong on scheme 3 before the reporters caught it. Added a once-per-process `opserr` warning (static-bool latch) in both full constructors when `mScheme == 3 \|\| mScheme == 5`, pointing at scheme 1 (ModifiedEuler) or 45 (RK45 Sloan) instead. See [[LEDGER_quirks]] for the static-flag caveat and the ssp+ManzariDafalias interaction. Gated by `tests/test_manzari_safety_pack.py`. | [#714](https://github.com/nmorabowen/OpenSees/pull/714) |
| `SRC/element/tetrahedron/TenNodeTetrahedron.cpp` | `// Ladruno`: **TIMs report item 8, TenNodeTetrahedron half.** `update()` called `materialPointers[i]->setTrialStrain(strain)` in the Gauss loop, discarded the return code (`success = ...` overwritten each iteration, never read), and unconditionally `return 0;` — so the element could never report a constitutive failure to the analysis, unlike its fork sibling `BezierTet10::update()`, which already accumulates the sum (`ret += theMaterial[gp]->setTrialStrain(...)`). Changed to `int success = 0;` at declaration and `success += ...` in the loop, `return success;` at the end — a pure accumulate-and-propagate fix, no numerics touched. **No dedicated regression test added** (a constitutive-failure-propagation probe on TenNodeTetrahedron was judged out of scope for this PR); `tests/test_manzari_safety_pack.py` and `tests/test_beziertet10_unsym_tangent.py`'s `TenNodeTetrahedron` control both continue to pass on the changed binary as an indirect no-regression check. | [#714](https://github.com/nmorabowen/OpenSees/pull/714) |
