| `SRC/material/nD/soil/PressureDependMultiYield.cpp`, `SRC/material/nD/soil/PressureDependMultiYield.h` | `// Ladruno`: **PDMY01 had no plastic strain at all** — it stores nested yield surfaces, the PPZ/dilation state and the current stress, but nothing you could contour to see where the soil actually yielded, so a failure mechanism (e.g. the ADR-79 punching-vs-general-shear question) could only be inferred from displacements. Adds one accumulator, `accumPlasticStrain()`, called once per **sub-step** inside `getStress()`, which splits that sub-step's strain increment with the SAME hypoelastic moduli `setTrialStress()` just used: `d_eps^p = d_eps − dev(d_sigma)/(2G) − (d_p/(3B))·I`, with `G`/`B` cached into `elasticShearMod`/`elasticBulkMod` at the bottom of `setTrialStress()` (they carry the pressure-dependent `modulusFactor` and the `Hv` volumetric-plasticity modification, so the inversion is exact by construction). Anything the elastic predictor did not produce is plastic: surface return in `stressCorrection()`, dilatancy through the plastic potential, and the `p <= 0` tension cut-off. Three new recordable channels: `plasticStrain` (tensor, engineering shear, 3-component in 2D matching the existing `strain` view), `equivalentPlasticStrain`/`plasticStrainEq`/`ebarP` (`int sqrt(2/3 de^p_dev:de^p_dev)` — the von Mises convention, deliberately the same as `LadrunoJ2`'s `ebarP`), and `volumetricPlasticStrain`/`plasticStrainVol` (signed trace — the dilatancy signal, which is the one a soil modeller reads). Trial accumulators restart from committed at the top of `getStress()` (that routine re-integrates the whole step from the committed state on every call) and are committed alongside the surfaces. **Passive on the response path** — the accumulators are write-only new members, nothing feeds back into stress or tangent; existing PDMY tests re-pass unchanged. **Wire format changed:** `sendSelf`/`recvSelf` grow by 7 doubles. **Corrected in a follow-up (see the row below): the 7 are APPENDED past the surfaces at `70+n*8 .. 76+n*8`, NOT inserted at 70.** Gated by `tests/test_pdmy01_plastic_strain.py` (8 cases): stage-0 accrues exactly zero; `ebarP` monotone; **an elastic unload window after yielding accrues 1e-19 against a 1e-6 scale** (the sharp gate — it proves the hypoelastic inversion is exact, moduli and all); a full numpy reconstruction from the recorded (stress, strain) history matching to **1e-9 relative** on every component; plastic compaction on a sub-PT-line path; and the 2D reduced view. Multi-sub-step integration cross-checked separately (a coarse `nSub=2` run lands on the same step-refinement curve as the fine `nSub=1` runs — 3.73e-7 vs 3.51e-7 — not the ~2x a double-count would give). **Note:** PDMY02/03 are separate classes and do NOT get this. The oracle's exactness depends on two upstream traps recorded in [[LEDGER_quirks]] (cohesion really defaults to `0.3` though the usage string says `.5`; `residualPress` is stored positive while `refPressure` is negative). | [#708](https://github.com/nmorabowen/OpenSees/pull/708) |
| `SRC/material/nD/soil/PressureDependMultiYield.cpp` | `// Ladruno`: **follow-up to the PDMY01 plastic-strain row above — make the `sendSelf`/`recvSelf` growth strictly ADDITIVE.** The first cut inserted the 7 plastic-strain doubles at slots 70..76 and pushed every yield surface from its upstream offset `70 + i*8` to `77 + i*8`. That was *self-consistent* — send and recv agreed, the round-trip passed, the numbers were right — but it **rewrote the vanilla layout** rather than extending it, which is precisely what §6 of [[../Ladruno_internal/WORKFLOW_GOTCHAS]] forbids for vanilla files ("strictly additive, never alter existing behavior") and which would make the eventual upstream diff gratuitously large. Now the surfaces stay on `70 + i*8` and the accumulators are appended at `pOff = 70 + numOfSurfaces*8`, so **the upstream layout is a strict prefix of ours**. No behaviour change and no numeric change — same 7 doubles, same values, different slots. **This does NOT restore cross-version database compatibility** and no honest fix can: `recvSelf` allocates `Vector data(...)` before the read, so an old file's shorter record still mismatches, and the `ID` header has no version field to negotiate with (adding one breaks the same way). A database written by a pre-#704 binary does not restore into a post-#704 one, full stop. What this buys is upstreamability and a minimal diff, not compatibility. **New gate:** `test_sendself_recvself_round_trip` — the format had **no coverage at all** before, which is what let the layout choice through unexamined. It save/restores through a `database File`, asserts every channel bit-identical, asserts the derived mobilised ratio (which is computed from `committedSurfaces[NYS].size()` and is therefore a direct probe of the surface block's offset), and then **keeps driving the model 10 steps** and compares against an uninterrupted reference. **Mutation-verified:** shifting only the `recvSelf` surface offset 70→71 sends the mobilised ratio to `inf` and the test fails — so the gate has teeth. Note the test pins `algorithm Newton`: `restore` resets the algorithm, Krylov's accumulator restarts with it, and PDMY commits `currentStress = trialStress` from the second-to-last Newton iterate, so a restarted Krylov run diverges ~6e-4 relative *with every byte of state correctly restored*; memoryless Newton reproduces to ~4e-14, which is what lets the assertion carry a real tolerance. | [#708](https://github.com/nmorabowen/OpenSees/pull/708) |
