| `SRC/material/nD/UWmaterials/ManzariDafalias.cpp` | `// Ladruno` **`OPS_ManzariDafaliasMaterial` wrote PAST a stack array on a deck with more than five trailing optionals.** `numArgs` is `19 + k` for `k` optionals, so `numData = numArgs - 19` is `k` — **uncapped** — and it was passed straight to `OPS_GetDouble`. `OPS_GetDoubleInput` (`SRC/api/elementAPI_TCL.cpp:316-329`) loops `for (i = 0; i < *numData; i++) data[i] = ...` with **no bound on the destination**, stopping only when the input args run out or a token fails to parse. The destination is `double oData[5]` (`:90`). So `nDMaterial ManzariDafalias 1 <18 doubles> 1 0 1 1e-7 1e-7 0 0 0` (k = 8) wrote `oData[0..7]` into a `double[5]` — **24 bytes over, on the stack**. Added a `numData > 5` guard that REFUSES the deck. **Refuses rather than truncates on purpose:** a silent truncation would run the deck with arguments the user did not get, which is exactly the ADR-86 §7.1 defect class (`OPS_SAniSandMSMaterial` silently dropping `TolF`/`TolR`) that this repair exists not to repeat. **Found by adversarial review during ADR-86 PR-3** (as an out-of-scope aside from the registration/parser lens), not by the ADR's own audit. **Gate:** `tests/test_manzari_safety_pack.py::test_optional_arg_count_is_bounded`, a genuine fail-before/pass-after test — pre-fix the eight trailing values are all valid doubles, so `OPS_GetDouble` reads all eight, returns success, and the material is CONSTRUCTED with no exception and no warning; the test asserts the refusal and therefore fails pre-fix. **Proven by mutation:** replacing the guard with `if (false)` fails that test and only that test. Nothing in the gate depends on observing the out-of-bounds write, which is undefined behaviour. **FAMILY SWEEP, surveyed and deliberately NOT fixed here** (reported, not hidden): the identical uncapped pattern is in `ManzariDafaliasRO.cpp:82` (`numArgs - 22` into `double oData[6]`), `PM4Sand.cpp:128` (`numArgs - 5` into `oData[24]`) and `PM4Silt.cpp:129` (`numArgs - 6` into `oData[24]`). `SAniSandMS.cpp:134` is **safe** from this — it bounds its reads with `std::min(numData, 3)` / `std::min(numData, 2)` — though it still carries the separate §7.1 silent-drop defect. Those three are one coordinated change with their own regression tests and are a scope decision, not an oversight. `OPS_LadrunoSANISAND` is immune to this whole family by construction: it never computes a count.
