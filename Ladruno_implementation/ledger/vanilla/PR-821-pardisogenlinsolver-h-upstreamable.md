| `SRC/system_of_eqn/linearSOE/pardiso/PARDISOGenLinSolver.{h,cpp}` | `// Ladruno ADR-75 P1k` (TIMs PM-01 D26): **`-stats` reworked to print the MUMPS-shaped labelled block after EVERY numeric factorization**, not once per sparsity pattern. P1d's original `-stats` latched on a `statsDone` flag reset only when the symbolic phase (11) re-ran — a Newton run refactorizing the SAME pattern (the `factored`-gate `else if` branch, phase 22) printed its memory counters exactly once, which hid every subsequent refactorization's numbers. `statsDone` is removed; a new local `didFactorNow` (true only when THIS `solve()` call actually ran phase 22) gates the print instead, matching how `MumpsParallelSolver.cpp` already prints inside `if (factored == false)` on every job=5. Reformatted to the MUMPS block's shape — `PARDISO stats: n=... nnz(A)=... matrixType=... threads=...` header (matrixType is PARDISO's own mtype 11/2/−2; threads is `mkl_get_max_threads()`, read back for the log only — no new SETTABLE thread option) followed by `  <label> iparm(N)  = <value>` lines using the **Fortran 1-based** numbering so every printed number is directly checkable against the MKL Developer Guide: `iparm(15)`=`iparm[14]` peak symbolic memory KB, `iparm(16)`=`iparm[15]` permanent memory KB, `iparm(17)`=`iparm[16]` numerical-factorization+solve memory KB (still read AFTER phase 33, unchanged from P1d — Intel documents it as a peak over factorization *and* solution), `iparm(18)`=`iparm[17]` nnz-in-factors, `iparm(19)`=`iparm[18]` Mflops-of-factorization (newly reported — P1d left this at a permanent 0; now set to `-1` before phase 11, exactly like the pre-existing `iparm[17]` nnz sentinel, ONLY when `-stats` is on, so it stays byte-identical otherwise despite Intel documenting it as costing analysis time). New `#include <mkl_service.h>` (unconditional — this translation unit is only compiled into the build when MKL is found at all, per `pardiso/CMakeLists.txt`'s `MKL_FOUND` guard, unlike the two command-layer files below which gate on the separate `_PARDISO` macro). The old perturbed-pivot/refinement-step diagnostic line is kept, appended after the new block. Alias: `setStats()`'s doc comment now names both `-stats` and `-pardisoStats`. | [#821](https://github.com/nmorabowen/OpenSees/pull/821) |
