Four-point ladder (5 repeats per arm, both arms back-to-back, minimum quoted): CMS/standard = 8.1x → 4.7x → 3.9x → 4.3x over n = 3 200 → 51 200 — **a flat ~4x** — with CMS fitting `n^1.12` against the standard solver's `n^1.34`, i.e. CMS scales slightly BETTER, not worse. **`O(n^4)` is retracted.** P4 remains UNMET on the time axis (~4x slower is a measured floor, no crossover anywhere), but the memory-capacity rationale is RESTORED and §4 of the P4 plan is again the real gate. **No automatic `k2` heuristic was shipped, deliberately** — the handoff's `sqrt(m)` rule is 1.4–8.7x off the optimum and its own ratio degrades (`n^1.78`, 11.3x → 37.5x), and the optimum sits beside a two-order-of-magnitude cliff that is non-monotone from below (at n=3200: k2=8 fast, 9/10/11 slow, 12 fast again), so neither "smallest converging k2" nor a generous rule is defensible on four points; the evidence-backed follow-up is a restarts-based *diagnostic warning* (P4 plan item 2b), not a rule. **That diagnostic is SHIPPED (ADR §33): `-restartWarn <n>`, default 8, 0 disables** — warns naming `-modesL2` when the T2 fixed-interface Lanczos restart count reaches the threshold, because a too-small `k2` does NOT fail: it *grinds* and then returns the correct answer, so in a batch queue it is indistinguishable from "the model is too big" and a campaign can collect false negatives without knowing. Three properties, each pinned by a check: it is **not** gated on `-verbose` (batch jobs never set it); the count is the **max across ranks** via `MPI_MAXLOC` on `{restarts, rank}` and the message names the offending rank — measured necessity, not caution, since on the 20x20 `k2=10` case rank 0's own counter reads 54 while the worst rank is at **131**, so a rank-0 warning would understate by 2.4x; and the threshold is absolute, **not** scaled off `-maxRestarts`, because raising that budget is precisely what a user does when thrashing. `-restartWarn 0` is legal (unlike `-maxRestarts 0`) since a diagnostic must be silenceable, and it stays out of the cross-rank consistency gate because it changes what is printed, never what is computed.
