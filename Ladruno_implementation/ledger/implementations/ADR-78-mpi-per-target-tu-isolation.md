| **MPI per-target TU isolation** ([[78_ladruno_parallel_contact_adr]]) — the fork's answer to a structural trap: anything in the `OPS_Analysis` OBJECT library is compiled ONCE with no parallel define and folded into every target, so an `#ifdef _PARALLEL_*` block written there compiles to **nothing in every binary, `OpenSeesMP` included**, while looking correct and leaving both happy paths bit-identical. Two files now carry the parallel-sensitive code out of that library and into `OPS_MPI_PER_TARGET_SOURCES`, which is added verbatim to all five targets so each copy gets that target's defines. **`LadrunoContactAbort.cpp`** (ADR-78 P1) — `ladrunoContactFatal()`, the single exit for a contact failure in `handle()`; under MPI with np>1 it `MPI_Abort`s rather than let a failing rank strand its peers in the next collective (measured: the pre-P1 job hung for minutes and left orphaned ranks holding the binary open, so the NEXT link failed `LNK1104`). **`LadrunoContactAbort.cpp` also carries `ladrunoContactNumRanks()`** (ADR-78 P2) — the MPI world size for the `-soft`-under-partitioning refusal; same TU for the same reason (an `#ifdef` probe in the handler would return 1 in every build). **`LadrunoAutoPenaltyReduce.cpp`** (ADR-78 follow-up) — `ladrunoAutoPenaltyReduce()`, the four `MPI_Allreduce`s that make `constraints Auto`'s `KMIN/KMAX/KAVG` global. Those had sat dead inside `AutoConstraintHandler.cpp` since the handler was contributed, so under MPI every rank sized its penalty from its OWN elements — and `PVAL` is exactly the fallback for a constrained node with no locally attached elements, i.e. a partition-straddling interface node. Behaviour moved verbatim (same collectives, order, `OPS_PARTITIONED` quick-return, warning strings); only the TU changed, which was the whole bug. **ADR-78 P4 finding 1 gave `ladrunoContactFatal()` its SECOND caller:** the three contact DECLARATION verbs in `SRC/interpreter/OpenSeesOutputCommands.cpp` (`contactSurface` / `contact` / `contactPlane`) are now thin wrappers routing any `<0` result through it, because #737 had moved missing-node detection into the parser where a `return -1` is rank-local — the refusing rank aborts its script and every peer blocks in the next collective (measured: P1's 1.1 s teardown became a 45 s hang with orphaned ranks). Wrapping the RESULT rather than the ~75 refusal sites also covers the refusals that propagate out of `addSurface`/`addContact`/`addRigidPlane`, and means a check added later inherits the teardown. The message lost its `LadrunoContactHandler:` prefix accordingly. **The rule this establishes: the OPS_Analysis-side file is left with NO `#ifdef _PARALLEL_*` at all** — the trap is not a wrong guard, it is that a correct-looking guard there is invisible, so removing it is what stops the silent reopening.
