| **ADR-92 P2-9 — the control-informed extrapolation factor `-implexFactor fixed\|control`** ([[92_ladruno_sanisand_implex_adr]] P2 table row P2-9; plan `_adr92_p2_9_control_informed_f_plan.md`) — extends the ADR-92 IMPL-EX work above (rows P2 and P2-7c). THE DEFECT, measured on Esmeralda at #807 acceptance: the P2-2 guard is (a) SANISAND-specific in its trigger (`Kp <= 0` / an `alpha_in` reset), (b) a THRESHOLD AT ZERO that under-fires — the engine that happened to fire at ~2x the points reached 10 % further on the twin's curve at no accuracy cost (honest wall 0.0177 vs 0.0169), and (c) REACTIVE — it reads the committed predecessor, so a trial that FIRST reaches a softening point is extrapolated at full `f`, and P2-6's retry rescues only where the pure elastic predictor already passes tol (322 rescues against thousands of refusals). THE REMEDY: the extrapolated stress is AFFINE in `f` on the frozen `Ce` — `sigma~(f) - sigma_impl = A - f*B` with `A = sigma_n + Ce:d_eps - sigma_impl` and `B = Ce:d_eps_p(n)` — so the distance to the `-implexControl` companion is minimised in CLOSED FORM by `f* = clamp((A:B)/(B:B), 0, f_max)`, with `f_max` = today's clock ratio `alpha*dt_{n+1}/dt_n`. The inner product is `DoubleDot2_2_Contr`, the one `GetNorm_Contr` and therefore `implexError` itself are built on, so the quantity minimised IS the numerator of the control's own error. `f* -> 0` exactly where the committed plastic increment points the wrong way (the P2-2 case, with NO model-specific trigger and one step EARLIER — at the trial, not from the predecessor); `f* -> f_max` where the history is right; `B:B == 0` (un-primed or elastic history) leaves `f_max` standing untouched, which is what keeps the P0 oracle's elastic rows byte-identical. Material-agnostic — it uses only `sigma_n`, `Ce`, `d_eps`, `d_eps_p(n)`, `sigma_impl`, which every IMPL-EX material holds, so the ADR-90 Lemaitre wrapper can adopt it unchanged. **FROZEN PER STEP:** `f*` is computed at the FIRST trial and held, so `f` is constant within the step and the delivered operator is still exactly `Ce` — the property that removed the subdivision ladder is not spent. "First trial of a step" REUSES the existing arm (`ladrunoImplexArmStep()`, i.e. the first `setTrialStrain` carrying a non-zero strain increment after a `commitState` or a `revertToLastCommit`) via a new transient `mImplexCtlFPending` — no second notion of freshness; a retry at a smaller dt reverts first, so it recomputes `f*` against its own new `f_max`, and every refusal site in `ladrunoImplexTrial()` already re-arms the step. **PRECEDENCE (decided here, not inferred):** the P2-2 guard runs FIRST and unconditionally inside `ladrunoImplexArmStep()`, so when it fires `f_max = 0` and the clamp can only return 0 — the guard wins outright, is NOT bypassed, and keeps its own census slot; `f*` replaces the guard's DEGREE only where the guard had nothing to say. Everything downstream (the W7 refusal, the `-implexControl` reduction floor, P2-6's trial-time `f = 0` fallback, `implexDetail[5]`) reads the `f` ACTUALLY USED, so the refusal machinery cannot be short-circuited by this flag. **REFUSALS:** `-implexFactor control` without `-implexControl` is REFUSED in `setLadrunoImplexOptions()` (no companion at the trial means nothing to aim at; the check is NOT gated on `verbose`, on the RED-1 F5 rule, so `getCopy(const char*)` and `recvSelf` clones are refused exactly as the deck is); `-implexFactor` without `-implex` joins the `-implexGuard`/`-implexTrialGuard`/`-implexFlipAbsorb` refusal list; an unparsable mode is refused with the fixed/control explanation. **REPORTING:** `implexDetail[5]` is unchanged in meaning — the `f` actually used — and now carries `f*` under `control`; `implexGuards` grown `Vector(6) -> Vector(7)`, new slot 6 = steps where the operator BACKED OFF (`f* < 0.5*f_max`), NOT counted when `f_max == 0` (no choice was available there — P2-2's slot 1 already records it). Echoed at construction and in `Print()` beside the other IMPL-EX flags. Wire `Vector(32) -> Vector(33)` (data(32) = `mImplexOpt.factorMode`); `mImplexCtlFPending` is NOT sent (transient, reconstructible from the arm, same rule as `mImplexStepArmed`/`mPrimed`). **`-implexFactor fixed` IS THE DEFAULT and reaches no new arithmetic at all**, so the operator is byte-identical to the pre-P2-9 build; `control` ships opt-in until the plan's dense-arm gate (Esmeralda honest wall >= 0.0177 on the twin within 0.3 %) is measured.
