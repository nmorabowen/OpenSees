| **WP-107 — threaded `Domain::update()` element loop (OpenMP), desktop-scoped** ([[107_ladruno_openmp_element_loop]]; implements [[75b_ladruno_threaded_assembly_adr]] stage L3-1). ADR-75b **closed** Lane 3 for the production/cluster path: G-L3 measured loop A at **0.26% of step at 540 675 DOF** under MUMPS, a **~42x** gate failure that gets worse with N. What it left standing is its own last paragraph -- *"Lane 3 is at best a desktop-only optimization on models <= ~136k DOF ... cited, not re-derived, if a desktop-scoped case is ever made."* The TIMs plane-strain strip (LadrunoQuad `-bbar` + LadrunoSANISAND, 10k-80k Gauss points, desktop solve) is that case, and its element kernel is a substepping critical-state model rather than G-L3's `J2Plasticity`. **What ships:** CMake `LADRUNO_OPENMP` (option default OFF; `build.bat` passes ON), the flag scoped to `OPS_Domain` + `OPS_Utilities` ONLY so PFEM's 7 dormant `#pragma omp` lines stay dead; `SRC/utility/LadrunoThreads.{h,cpp}` as the single thread-count knob (ADR-75b P-5) with the `ladrunoThreads` verb in all four interpreter paths and the `LADRUNO_THREADS` env seed, **default 1**; and `Domain::ladrunoThreadedUpdate()`, a `#pragma omp parallel for schedule(dynamic,8) num_threads(n)` over a **snapshot** of the element iterator. **Bit-identical by construction, not by tolerance** (ADR-75b section 2.1): `Domain::update()` has no reduction into the SOE, so the threaded loop does the identical arithmetic in the identical order; `ok` is an INTEGER `reduction(+:)` and the reported failing element is the lowest index in serial order (a `critical`, not `reduction(min:)`, because MSVC is OpenMP 2.0). **The five hazards ADR-75b section 5.4 said grep could not see are each answered:** H2 -> a per-class `Element::ladrunoThreadSafeUpdate()` allowlist that is **default FALSE** and **all-or-nothing** (one un-audited element -> the whole loop runs serial, naming the tag); H3 -> the shared mutable cursor is drained into a `std::vector` first; H4 -> a serial pre-pass forces `createDisp/createVel/createAccel`; H6 -> **refuse** while the deep profiler gate is armed; H7 -> `ops_TheActiveElement` is now `thread_local`. `PartitionedDomain`/`Subdomain` refuse outright, so SP/MP are untouched and ADR-75b section 11 q6 (hybrid MPI+threads) stays deferred. **On the allowlist:** `LadrunoQuad` std/bbar/ssp under `-geom linear` (its `update()` scratch is now stack-backed and `shp`/`shpBar` are `thread_local`); `ManzariDafalias` under **IntScheme 1 only**; `LadrunoSANISAND` additionally only with `-implex` OFF; `ElasticIsotropicPlaneStrain2D`. **Explicitly NOT shipped: loops B/C** (`formTangent`/`formUnbalance`) -- `FE_Element::theTangent` is a class-wide pool (ADR-75b 5.4-H1, a 100% collision no element allowlist can fix) and `LadrunoQuad::K`/`::P` are class-static too; de-pooling both is ADR-40 rank-7 work with a GB-scale SERIAL memory cost (ADR-75b section 11 q9). (2) `tests/test_wp107_threaded_update.py` gains a module-level `skipif` driven by a child-process probe of the binary's own warning, so a deliberate `-DLADRUNO_OPENMP=OFF` build skips with a reason instead of failing 10 times -- biased to RUN on every ambiguous outcome (crashed child, missing marker, single-hardware-thread box), because a file that silently skips on CI would re-create the un-gating this fix removes.
