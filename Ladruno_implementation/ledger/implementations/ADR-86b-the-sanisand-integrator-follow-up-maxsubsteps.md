| **ADR-86b — the SANISAND *integrator* follow-up: `-maxSubsteps`, the `TanType` default, and the element that carries a material failure** ([[86_ladruno_sanisand_adr]] follow-up; driven by [[_adr90_tau0_qu_band]] §5/§6.3 and ADR-90 §8.1's proposed close-out) — the small, fork-owned work package ADR-90 handed back to ADR 86 after GATE U showed the constitutive integrator, not the stepping controller, was the binding resource. **T1 `-maxSubsteps N`** on `nDMaterial LadrunoSANISAND`, **default 0 = UNCAPPED so every existing deck is byte-identical**, wired through a new vanilla flag seam `ManzariDafalias::mMaxSubstepsInME` exactly as `-honorTolR` is wired through `mHonorTolRInME` (see [[LEDGER_vanilla_files]]). Past the cap `ModifiedEuler` **fails the update instead of force-accepting** — the ADR-84 `strict_convergence` precedent — leaving the committed state untouched, so `setTrialStrain` can return `-1` and the analysis' own step-cut/subdivision logic finally has something to react to (GATE U used **0 of 80** subdivisions while single steps ran 34 min, precisely because the integrator never failed). Both wrappers return the status; a throttled process-budget `opserr` line names tag/`T`/`dT`; `eleResponse <ele> material <gp> substeps` returns `[substeps_taken, cap_hit]`. **T1 also required a fork-element repair:** `LadrunoBrick::update()` **discarded** `setTrialStrain`'s return code on four of its five paths (std/b-bar, SSP, and both URI branches — only `updateHypo`/`updateFinite`/EAS propagated), so a material failure could not reach the analysis at all. The obvious repair -- honour any `< 0` -- is WRONG and was measured to be: it broke `test_ladrunoBrick_asdconcrete_bend.py`'s two long-green mesh-objectivity gates, because `ASDConcrete3DMaterial` returns a negative code meaning "an inner iteration missed, here is my best state" (the case ADR-33/34 settled the other way). ADR-86b therefore introduces a distinguished sentinel, **`LADRUNO_MATERIAL_REFUSED`** (`SRC/material/LadrunoMaterialStatus.h`, `-33086`) = "the increment was NOT integrated, the committed state is unchanged"; the four paths propagate ONLY that value, every other code keeps its previous treatment, and adopting it cost zero behaviour change elsewhere. **Correction (review-fix pass):** the claim that `updateHypo`/`updateFinite` both "keep their pre-existing `< 0` tests" is FALSE for `updateHypo` — `updateHypo` and `formEAStrue` are sentinel-aligned (`== LADRUNO_MATERIAL_REFUSED` only, matching the four repaired paths); `updateFinite` ALONE keeps a blanket `< 0` test, because `setTrialF` is a different interface (`FiniteStrainNDMaterial`) that no material returns an advisory negative on. Narrowing `updateHypo`/`formEAStrue` surfaced a real regression this ADR did not anticipate: ADR-84's `strict_convergence` rejection was a bare `-1`, which a blanket `< 0` caught but the sentinel-only check does not — fixed at the producer by changing that rejection to `LADRUNO_MATERIAL_REFUSED` too (see [[LEDGER_vanilla_files]], `ASDPlasticMaterial3D.h`). Upstream `stdBrick` still swallows return codes, which is why every gate here uses `LadrunoBrick` — **`LadrunoBrick` is today the ONLY element that propagates the refusal; under `Brick`/`BrickUP`/`QuadUP`/`stdBrick` the return code is discarded, so `-maxSubsteps` must not be used on those elements — a capped run there is silently INVALID, not merely un-cut.** **T2** the fork parser's `TanType` default **0 → 2** (`LadrunoSANISAND.cpp`); vanilla's stays 0 (verified at source, `ManzariDafalias.cpp:93`) because its golden files depend on it, and the material now ECHOES the tangent it will run so the divergence cannot be silent. **T3/T4 are docs, no code:** convergence-test guidance (`NormUnbalance` scaled to `gamma*V`, never `NormDispIncr`) and the `-Presidual` decision, both written up in [[86_ladruno_sanisand_apegmsh_emitter_guide]] §6/§7 and [[86_ladruno_sanisand_handoff]] §3/§5b — **no default changed**.
