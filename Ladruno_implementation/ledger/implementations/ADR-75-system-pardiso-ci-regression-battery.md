| **`system Pardiso` CI regression battery** ([[75_ladruno_sparse_direct_strategy_adr]]) — pytest gate for the desktop PARDISO solver, closing the ADR-75 review gap that every correctness claim lived only in offline bench scripts no CI runs (`Ladruno_files/testbed/perf/phase1/`). 8 tests on a plastic LadrunoBrick+LadrunoJ2 cantilever (~300 DOF, tangent changes between iterations so the reuse paths are actually exercised): UmfPack parity (P1/P1b), `-matrixType 1/2` exactness (P1d), the ModifiedNewton phase-33 `factored`-gate path (P1), `-krylov` CGS parity + the `factorsCurrent` staleness guard (P1e, rtol 1e-6 — eps_CGS-limited), the mtype −2 `-krylov` refusal warning, `-stats` prints the MUMPS-shaped labelled block after every factorization (P1k, superseding the original once-per-pattern behaviour — see the P1k row below and `tests/test_pardiso_stats.py`), the profiler phase-split brackets (soe.symbolic/factor/trisolve/cgs + dc.s.fill/verify + deep `soe.addA`, asserted as HDF5 group names on raw report bytes with a coarse-run deep-gating negative control — see the [[LEDGER_vanilla_files]] instrumentation row), and the P1d degrade-not-null parse rule (the historical string-`-matrixType` trigger; asserts no ProfileSPD fallback). Tolerances hold at any MKL thread count (threaded PARDISO is not byte-reproducible run-to-run, P1f — nothing asserts bitwise equality). Zone-A + skipif non-win32 (FEAST gating pattern); a no-MKL Windows build skips via the factory's "has no MKL" warning rather than passing vacuously. **Extended (TIMs defect report item 2, PR [#713](https://github.com/nmorabowen/OpenSees/pull/713)): the `addA` half-storage asymmetry guard now RE-ARMS periodically** — it used to sample only the first `ASYM_CHECK_BUDGET`=3 tangent assemblies (armed in `setSize`, spent in `zeroA`), so a tangent that turns unsymmetric LATER (non-associated flow after first yield — ManzariDafalias measures 4-6%; a contact pair closing at step 50) burned the budget while still elastic and was never checked again; the in-source comment admitted this as a flat LIMITATION. A new `asymPass` counter re-arms the budget every `ASYM_RESAMPLE_PERIOD`=64 assemblies while `asymWarned` is unlatched, so the guard samples startup AND periodically and late-onset asymmetry is caught within ≤64 assemblies of appearing; the warning now also reports the assembly number so it can be correlated with the load step. ADR-75's performance contract holds: steady-state duty cycle is 3/64 ≈ 4.7% of the mirror-compare cost (itself the cheap part of `addA` — idSize²/2 in-cache subtractions against an idSize² binary-searched scatter), 96.9% of assemblies pay one modulo in `zeroA`, and the once-per-SOE `asymWarned` latch is untouched. That closes this row's former "NOT covered" gap: new `tests/test_pardiso_asym_rearm.py` (non-associated DruckerPrager cube, `-matrixType 2`) asserts the warning fires AND that the assembly it reports is past the startup window — unreachable pre-change, so the gate is real — plus an ElasticIsotropic `-matrixType 1` no-false-positive control over a run several re-arm periods long and a `-matrixType 0` full-storage control. The solver/SOE source rows live in [[LEDGER_vanilla_files]] (upstream Salehi files). **Extended again (ADR-75 P1k, TIMs PM-01 D26): new `tests/test_pardiso_stats.py`** asserts the full `-stats`/`-pardisoStats` block (n/nnz(A)/matrixType/threads header + the five `iparm(15..19)` lines, factor-entry count a positive int), the `-pardisoStats` alias, the block's ABSENCE with no flag, and that a SECOND refactorization of the same sparsity pattern (two LoadControl steps) prints its OWN block — the "once per pattern" claim `test_pardiso_solver.py::test_stats_prints_labelled_block` used to make no longer holds by design, since a Newton run refactorizing one pattern repeatedly is exactly the case TIMs PM-01 D26 needs every entry of. | Tests (pytest, zone_a) | — | `tests/test_pardiso_solver.py`, `tests/test_pardiso_asym_rearm.py`, `tests/test_pardiso_stats.py` | shipped | [#713](https://github.com/nmorabowen/OpenSees/pull/713), [#713](https://github.com/nmorabowen/OpenSees/pull/713), [#821](https://github.com/nmorabowen/OpenSees/pull/821) |
