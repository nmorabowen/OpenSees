| **WP-184 — `ladrunoSchema` v0** (apeGmsh#1667, program link F3; consumed by apeGmsh `BackendInfo` in F4). One new interpreter command, in classic Tcl and in the DL engines (TclWrapper, Python), returning ONE JSON string, compact and key-sorted at every level, with no paths or timestamps: `{"build": <ladrunoBuild>, "commands": [sorted rows of LadrunoCommandTable.h this engine registers], "engine": "dl"\|"classic", "options": {<owner>: {<token>: {"nargs": n\|"list", "since": "<PR/WP>"}}}, "schema_version": 0}`. Everything is generated: `commands` from the X-macro table (columns stringified, so no entry point is referenced and one header serves both the classic and the DL link), `options` from the new `ladruno_opt::kOptTables` registry in `SRC/material/LadrunoOptSpec.h` (one row per fail-closed parser: owner name + table; today `LadrunoRCConcrete` and `LadrunoRCFiniteStrain` on `kLadrunoRCOptions`). Fail closed: any argument is refused (Tcl error / Python exception), and a duplicate command, owner or token makes the command fail rather than emit ambiguous JSON. Gate: `tests/test_wp184_ladruno_schema.py` (zone_a: exact JSON round-trip, `build == ladrunoBuild`, `commands` == the table's rows per engine, `options` == the header declarations, pinned `since` anchors, bad arguments raise in both engines, and every `ladruno_opt::reportUnknown` call site's (name, table) pair has a `kOptTables` row). | interpreter infrastructure | — (no class tag) | `SRC/interpreter/LadrunoSchema.h` (new), `SRC/interpreter/LadrunoCommandTable.h` (row), `SRC/material/LadrunoOptSpec.h` (`kOptTables`), `SRC/interpreter/OpenSeesOutputCommands.cpp`, `SRC/interpreter/OpenSeesCommands.h`, `SRC/tcl/commands.cpp`, `Ladruno_scripts/stamp_headers.py` (GLOBS), `tests/test_wp184_ladruno_schema.py` (new) | PR open | — |
