| **WP-101 — `LadrunoKinematicCoupling` within-step augmented Lagrangian (`-alUpdate`) + `K_t` conditioning guard** (guide [[LadrunoKinematicCoupling_guide]] §3.1/§4.2; ADR [[29_ladruno_kinematic_coupling_rbe2_adr]]). **The defect:** `-enforce al` advanced its Uzawa recursion ONCE PER COMMITTED STEP (`commitState`: `λ += D g`) — a first-order Uzawa *across* steps. Within one step the tie was therefore penalty-only, so a short push (a footing push, a single `sp` step, a staged activation) never converged the constraint: measured on a rigid-footing-on-soil gate at `K_t = 1e6`, `-enforce al` returned **exactly** the penalty gap `1.63e-2` of the push. **The fix (after adversarial review round 1 — the FIRST cut of this WP was MERGE-BLOCKED):** the cadence stays `commit` by DEFAULT and the within-step closure comes from an **OUTER Uzawa loop**, not from moving the update inside Newton. Moving it inside (`-alUpdate iter`) makes the residual **path-dependent** — `update()` advances λ BEFORE the force is formed, so the tie force carries `λ_k + 2·D·g(u_k)` against a tangent that linearises a single `D·g`, and λ_k depends on the iterate history — so the residual is not a function of `u` and every secant / accelerated / re-solving method is fed `(δu, δr)` pairs describing no Jacobian. **Measured regressions vs the tip:** DisplacementControl fails 5/5 steps with EVERY algorithm (geometric stagnation at ratio 0.978, no maxIter rescues it, because it re-solves dLambda each iterate); KrylovNewton (the fork's recommended algorithm), BFGS and Broyden fail or diverge under LoadControl (Broyden to 2.5e275); ModifiedNewton survives a linear model but fails 10/10 on a LadrunoBrick bbar + LadrunoJ2 host. `iter` therefore survives only as an EXPERT opt-in, **refused at the first update()** unless the active algorithm is full Newton AND the active static integrator is LoadControl (read via `OPS_GetAlgorithm` / `OPS_GetStaticIntegrator` / `OPS_GetTransientIntegrator`; silent while no analysis exists so the `Domain::addElement`-time update() does not trip it). **THE WITHIN-STEP ROUTE THAT WORKS NEEDED NO NEW CODE:** the fork's ADR-41 D1 held-load augmentation sweep (`ladrunoBeginAugment` / `integrator LoadControl 0.0` / repeated `analyze 1` / `ladrunoEndAugment`) already IS an outer Uzawa loop, and LadrunoKinematicCoupling participates with **no hook, no registry, no new virtual** — `Domain::commit()` runs every element's `commitState()` during the sweep (`Domain::contactAugmenting` only suppresses the recorder loop and the commitTag bump), and with `-alUpdate commit` that commitState IS the outer update. Each held-load pass is an inner solve at FIXED λ, so the residual is well-posed and EVERY algorithm works. Measured: **20/20 cells** (Newton / ModifiedNewton / KrylovNewton / BFGS / Broyden × LoadControl / DisplacementControl × NormUnbalance / NormDispIncr) close to **6.14e-11** (LoadControl, 5 passes) / **9.53e-10** (DisplacementControl, 4 passes) from a penalty floor of 1.63e-2. Use `LoadControl 0.0` for the held passes whatever drove the real step — a zero-increment DisplacementControl is degenerate. The tangent stays the pure penalty operator `BᵀDB` (`λ` frozen w.r.t. `u`), so with a linear structure one Newton solve IS the Uzawa inner solve and the multiplier error contracts by `(I + D B S⁻¹Bᵀ)⁻¹` per iteration (radius `1/(1+λ_min)` — **stiffer `K_t` converges FASTER**, the opposite of the penalty method's conditioning penalty); stationarity forces `D g = 0`, so the converged state satisfies the constraint EXACTLY rather than to the penalty's `O(1/K)` floor. `-alUpdate {commit|iter}`, **default `commit`** (unchanged behaviour); under full Newton + LoadControl `iter` does reach `2.98e-14` in ONE step, and it tracks the DISPLACEMENT tolerance, not the gap (NormDispIncr 1e-14 → 2.98e-14 in 9 iterations; 1e-8 → 2.68e-9 in 6; 1e-6 → 1.25e-7 in 5; at maxIter 3 it FAILS while penalty converges in 2) — 5-9 iterations where penalty needs 1-2. **Three correctness follow-ons the per-iteration update forces:** (a) `revertToLastCommit` was a bare `return 0` — with `λ` moving inside a step a failed/retried step would inherit the multipliers of a DISCARDED trial state, so `λ` is now snapshotted at `commitState` (`lambdaCommitted`) and rolled back; (b) **`Domain::revertToLastCommit()` and `Domain::revertToStart()` both end with `return this->update();`** so every element's `update()` fires once more on the just-reverted state — un-latched that ratcheted `λ` on the state it had just rolled back to (measured 1.5e-10/failed step); a one-shot latch armed by the revert and consumed by the induced call closes it ([[LEDGER_quirks]]); (c) `sendSelf`/`recvSelf` carry `alUpdate` (header slot 20, **version 2** — and a NEWER version is now refused rather than mis-read) and `lambdaCommitted` (payload `3·nGap`); **`Domain::recv()` also calls `update()` right after `recvSelf`**, so the latch is ARMED there too (un-armed, a database save/restore moved λ by 6.6e-9 under `iter`). (d) `resolveAutoKt()` no longer latches `ktResolved` on a FAILED host lookup: `Domain::addElement` calls `update()` at DECLARATION time, so a deck that declared the coupling BEFORE its `-host` latched on that miss — `-k auto` silently stayed at 1e12 instead of 7.93e6 and the conditioning warning could never fire (pre-existing; fixed here). (e) a one-time warning when `-enforce al` meets an **EXPLICIT** integrator: AL is refused-by-consequence there because `-bipenalty` is dropped when `-enforce al` is given, leaving a massless tied DOF with no mass source — measured under CentralDifferenceLadruno: `penalty -bipenalty` returns 0 (runs), `penalty` alone and `al -bipenalty` both return -2. A parse-time refusal is impossible (the integrator does not exist at declaration). **Review r2 narrowed this**: the first cut tested `TransientIntegrator != 0`, which also fired for IMPLICIT transient — `-enforce al` under Newmark + Newton works perfectly (measured 0/10 failed, final max|g| 1.5e-8) and was being told it was "refused-by-consequence … singular". Now gated on an enumerated explicit class-tag set (CentralDifference*, ExplicitDifference*, ExplicitBathe*, CentralDifferenceSMS*, CentralDifferenceLadruno), with unknown transient tags treated as implicit so a new integrator never inherits a false warning. (f) **augmentation-sweep hygiene** (r2, 3 vanilla files, ledgered): a `ladrunoBeginAugment` without its `ladrunoEndAugment` does not fail — it silently voids EVERY later recorder sample (next step ok=0, time 1→2, recorder file EMPTY), because the flag makes `Domain::commit()` recorder-silent. A second Begin without an intervening End now WARNS, and the flag is cleared by `Domain::clearAll()` (wipe) and `OpenSeesCommands::wipeAnalysis()`. This is ADR-41 infrastructure that WP-101 promotes to a mainstream workflow, so the touch is minimal: one warning + two resets. **Plus the `K_t` selection rule** (guide §3.1): rigidity error `err = c/K_t` exactly (gate: `c = 1.66e4`, constant to 5 digits over `1e6…1e12`; TIMs strip `5e9 → 6.7e-7`, `1e12 → 5.7e-8` = the round-off floor) versus conditioning ∝ `K_t` (TIMs strip, **101 583 DOF**: `1e12` drove **Pardiso onto perturbed pivots and then to failure** and **SuperLU failed its first factorisation**, while `5e9` carried the same leg to a clean plateau) ⇒ recommended band **`1e2…1e4 × k_host`**, with a once-only WARNING above `1e6 × k_host` when a `-host` is named. The warning lives in `resolveAutoKt()` NOT the parser (at parse time the host may not be in the domain, nor have had `setDomain()` called ⇒ `getInitialStiff()` is a null-node deref waiting to happen). **And the `-k auto -host` documentation gap**: it is a CONDITIONING control inherited from [[LadrunoEmbeddedNode_guide]] §3 (`K_u = a·max|K_host(i,i)|`, `a = 1e3`, "mesh- and material-independent in conditioning"), restricted by ADR 29 §6 to an explicit `-host` because an RBE2 node set has no single host — it is **NOT a rigidity setting and cannot hold a rigid footing** (TIMs gate `1.4e-4`; Zone-A gate resolves `K_t ≈ 7.9e6` ⇒ `2.1e-3`).
