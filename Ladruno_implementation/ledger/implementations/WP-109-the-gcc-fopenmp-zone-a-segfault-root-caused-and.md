| **WP-109 — the gcc `-fopenmp` Zone-A segfault root-caused and fixed; `LADRUNO_OPENMP` defaults ON** ([[75b_ladruno_threaded_assembly_adr]] §14.5). #843 banked a deterministic exit-139 in `test_adr30_projection_p0.py::test_massless_dof_is_not_policeable_by_the_soe_layer` on gcc as "codegen/link turning the singular-mass path into a crash" and left the CMake default OFF, so Zone-A never ran the WP-107 warrant. **Reproduction:** a fresh shallow clone on esmeralda (gcc 11.4 / 22.04, Release+`-g` and ASAN trees, OpenMP ON) does NOT reproduce — Tcl twin, Python twin and the real file all pass — so a `workflow_dispatch` debug workflow ran the suite under gdb on ubuntu-latest (gcc 13.3 / glibc 2.39), where it reproduces every time. **Faulting frame:** `std::codecvt<char16_t>::do_unshift` ← `std::ostream::_M_insert<long>` ← `PythonStream::err_out<int>` ← `DiagonalDirectSolver::solve` (`opserr << i`, the `aii = 0` refusal): a `std::stringstream` asked its locale for `num_put` and got a `codecvt` facet — **two libstdc++ runtimes in one process**. **Root cause (build):** the GNU branch's `CMAKE_EXE_LINKER_FLAGS "-static-libstdc++"` leaks into `FindOpenMP`'s executable probe, which records `OpenMP_CXX_LIB_NAMES = libstdc++;gomp;pthread` (`OpenMP_libstdc++_LIBRARY = …/libstdc++.a`); WP-107 appended `${OpenMP_CXX_LIBRARIES}` to the SHARED Python modules, which also `DT_NEED` `libstdc++.so.6` — the esmeralda module exported 179 libstdc++ internals and `LD_DEBUG=bindings` showed `num_put::id` bound to both copies; which copy wins per symbol is load-order luck, hence gcc-13-only. **Fix:** probe with the EXE flags cleared + link only `LADRUNO_OPENMP_LINK_LIBS` (OpenMP runtime, rest dropped loudly, `FATAL_ERROR` guard) + default ON. **Pinned:** `tests/test_wp109_module_single_libstdcxx.py` (zone_a; pure-Python ELF `.dynsym` reader — the module defines no `std::locale`/`std::ios_base`/`codecvt<char16_t>` symbol and NEEDs `libstdc++.so.6`; PE skips with a reason; mutation gate: 179 leaked → red, 0 → green, measured). **Verification:** esmeralda relink 0 leaked + 4/4; runner gdb + ASAN on the fix; `ladruno.yml` dispatched on the branch (run 35173119941) — Zone-A green, **2500 passed / 118 skipped / 3 xfailed** with `test_wp107_threaded_update.py` **18 PASSED, 0 SKIPPED** on gcc 13 (#843 baseline 2481/136: +19/−18), the crashing test PASSED, gdb job 2562 passed exited normally.
