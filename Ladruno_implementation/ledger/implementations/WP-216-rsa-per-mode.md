| **WP-216 — `responseSpectrumPerMode`** ([[214_ladruno_rsa_per_mode_output_adr]], program #1024 link P1) — `responseSpectrumPerMode (-ts $tag \| -Tn .. -Sa ..) -dir $d.. <-scale $s> <-modes $k..> <-reactions> <-reactionSet $name $node..> <-eleGroup $name -ele $e.. <-cut $node..>> <-inertia $name $node..>`, each group with an optional `-about $x $y <$z>`. Returns, for every requested direction and mode, the base reactions (every SP node, SP-constrained DOFs only), named support sets, element-group resultants at a cut (summed `eleForce`) and modal inertia resultants (M φ s Γ Sa), each as the increment over the committed state, flat [dir][mode][component] in a dict with `shape`, `period`, `saPeriod`, `omega`, `term` (ADR 213 D3b rigid term), `kind`, `Sa`, `gamma`. Same amplitude as `responseSpectrumAnalysis -mode k -increment` (same expressions; `check()` and `getSa()` made public); updates only the elements attached to a support and the named groups, in the `-increment` revert / update / set / update sequence, never the whole domain; one `revertDomainToLastCommit` per call, domain left committed. Gate `tests/test_wp216_rsa_per_mode.py`: equals the stock loop to 1e-12 of the term scale per mode under Transformation / Penalty / Lagrange and on a ritzVectors set, and within the loop's own history spread on a residualModes (`-period`) set; refusals. Found and fixed on the way: `TransformationFE` kept one count per node in a 64-int static buffer, so an element with > 64 nodes (a LadrunoMembrane floor) corrupted the heap under Transformation.
