| **WP-196 — the commit phase's cost** ([[196_ladruno_commit_phase_cost_adr]]; follows WP-192, issue #959). Profiled first (new scopes `commit.nodes/elements/record`, `rec.<kind>`, `eb.*`, `lr.*`): on the rev3 1D window at 2 ranks the non-element commit is ~all `EnergyBalance` (807 of 822 ms on the critical rank; the four `recorder ladruno` files ~15 ms, MPI 0), and inside it the `getDamp()` tangent (44 %) and the WP-184 check (40 %: a second residual + tangent + 2 masses). **What ships:** (1) `ebkernel::elementEnergyTerms` — one element's terms, bitwise the old per-element arithmetic, mass in a per-thread scratch; (2) new opt-in `Element::ladrunoEnergyRayleighOnly()` (default false) lets the kernel skip the WP-184 check, which always answers "no" for exact Rayleigh damping; ASDShellQ4 opts in without a Damping object and with `-noeas`; `LADRUNO_EB_LEGACY=1` forces the check; (3) `EnergyBalanceRecorder` forms the terms into one slot per element (maximal runs of `ladrunoThreadSafeForm` elements on `ladruno_parallelFor`, others serial in place) and reduces them in the live element order, so files are byte-identical at any thread count (`LADRUNO_THREADS_LOOPS` bit 16, default mask 31). **Verified:** 1D serial window byte-identical (text files; all 257 `.ladruno` datasets) base vs WP-196 at 1 and 8 threads; `tests/test_wp196_energy_commit_phase.py` (legacy vs default, 1 vs 2/4 threads, dashpot, EAS shell); 108 energy/recorder/threading tests green. **Measured** (critical rank, 2 ranks): step 4 244 -> 3 796 ms at 1 thread, 2 323 -> 1 654 ms at 8 threads (commit 921 -> 194 ms).
