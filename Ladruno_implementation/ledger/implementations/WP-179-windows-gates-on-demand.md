| **WP-179 — Windows gates, on demand** (setup [[WINDOWS_RUNNER]]; issue #934). `.github/workflows/ladruno_windows.yml` is a `workflow_dispatch`-only job (no schedule, no PR trigger, not required) on `[self-hosted, windows, ladruno-win]`. It forces a CMake reconfigure so `ladrunoBuild()` is re-stamped, builds all 5 targets with `build.bat` (which byte-verifies `dist\`, WP-178), then runs the tests through `Ladruno_scripts/ci_run_pytest.py`. The launcher requires `python -S`, pins `dist\bin` for itself and its children, asserts the engine file, and requires `ladrunoBuild() == github.sha` (exit 90 = wrong or stale engine, 91 = no `-S`, outside pytest's 0–5). `scope=platform` selects tests with `python ci/check_quirk_patterns.py --list-platform-tests`: every collectable `test_*.py` of ANY tier with a non-portable platform branch, from lint L8's own AST walk, so no list is maintained. It currently finds 12 files, including 3 non-`zone_a` files that no CI ran at all. Label `ladruno-win`, not `ladruno-perf`, so registering the desktop leaves the 06:00 UTC nightlies dormant.
