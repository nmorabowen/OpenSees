| **WP-253 — mode F on threads** (#1097, program #1075; pre-registration and results `Ladruno_implementation/253_mpm_performance.md`). **Instrumentation:** coarse profiler scopes `mpm.f.admissible` and `mpm.f.dtcrit` in the host, and under `mpm.advance` `mpm.f.support / p2g / grid / g2p / project2 / update / commit`, plus `mpm.f.transpose` on the threaded path. The core stays OpenSees-free: an optional `PhaseHook`, null by default, implemented by the host with `ScopedTimer`s on the calling thread. **Threads:** `ladrunoThreads n` (`ladruno_loopThreads`, `ladruno_parallelFor`) threads mode F's step. At 1 thread the serial `Engine::advance` runs unchanged. At n threads (`LadrunoMPMThreads.h`) the result is bit-identical by construction: supports are built count / prefix / fill; P2G mass, momentum and external and internal force (with the anti-locking corner term in the serial interleaving) and the second projection are node-centric gathers over a deterministic node-to-entry transpose (per-block histograms, ascending entry order = the serial summation order); slaved ghosts fold in the serial first-touch order; grid-node and particle loops are parallel; reductions are max or lowest id. The material calls thread only when every particle material answers `ladrunoThreadSafeUpdate() && ladrunoThreadSafeForm()` (3D ElasticIsotropic among the admitted ones). Otherwise: parallel kinematics, then serial material calls in particle order, then a parallel push. Failures name the lowest failing particle with the serial text. On that split path the pool's workers sleep through the serial material and commit loops (`ladruno_ompQuietBegin/End` in `LadrunoThreads.{h,cpp}`: libiomp's `kmp_set_blocktime` resolved at run time, a no-op without it).
