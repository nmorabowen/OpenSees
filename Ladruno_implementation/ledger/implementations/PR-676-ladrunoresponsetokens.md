| **LadrunoResponseTokens** — one canonical vocabulary for element recorder tokens, plus the gap-closing sweep it enabled. **The disease:** upstream every element hand-rolls its own `strcmp(argv[0], ...)` chain in `setResponse`, so the accepted spelling of the SAME quantity drifts — vanilla `Brick` takes `stresses` but not `stress`, `FourNodeQuad` takes both. The fork copied that drift into 8 new continuum elements and added its own on top, and the failure is SILENT: `recorder Element ... stress` writes an empty file on a `LadrunoBrick` and data on the `LadrunoQuad` next to it, which reads as “the quantity is zero”, not “you spelled it wrong”. **The cure:** a header-only alias table (`LadrunoResp::is(argv[0], "stress")`) that folds singular/plural and every registered synonym. Matching is **symmetric** (`is(a,b)` ≡ same canonical row, so an element cannot pick the “wrong” spelling to test against) and an unregistered token degrades to an exact `strcmp`, i.e. never worse than upstream. **Invariant, load-bearing:** an alias NEVER changes the emitted `ResponseType` labels / response ID / vector width — otherwise a recorder’s column headers would depend on the spelling in the user’s script and MPCO/STKO readers would break. **Gaps closed (these are missing responses, not spellings — aliases alone would not have fixed them):** the family contract `force / stress / strain / stiff / stiffInitial / charLength` now holds on all 8 fork continuum elements — `LadrunoSolidShell` had NO force and NO charLength response at all, `LadrunoUP` had no force, strain, stiff or charLength, `LadrunoCSTPair` had no strain, and the whole plane family (Quad/CST/LST/CSTPair) had no stiffness (the FD-tangent diagnostic Brick and SolidShell already shipped). **The base-class chain:** `Element::setResponse` is a real implementation serving `globalForce`/`dampingForce`/`dynamicForce`/`inertialForce`, and exactly ONE fork element delegated to it (`LadrunoDispBeamColumn2d`; its own 3d twin did not) — so those four were unavailable fork-wide. All 16 fork elements now chain, `getResponse` included, using the 2d twin’s pattern: `output.endTag()` FIRST, because the base opens its own `ElementOutput` tag ([[LEDGER_quirks]]). **Penalty/tie family levelled:** `penalty` now accepted on both couplings (was `kt`/`k` only), `k` on `LadrunoEmbeddedRebar` (was `kt`/`penalty` only), and `penaltyEnergy` + `constraintViolation` added to both couplings (they existed only on EmbeddedNode/Rebar). `massPenalty` deliberately NOT added to `LadrunoKinematicCoupling`: it lumps a per-DOF DIAGONAL bipenalty mass (`*M0`), not the single scalar the rest of the family reports, and one token with two widths is worse than an honest absence. **`LadrunoIMKBeam`/`2d` realigned on the DispBeamColumn vocabulary:** `chordRotation` == `chordDeformation` == `basicDeformation` == `deformation`, `plasticRotation` == `hingeRotation`, plurals throughout — and `localForce` is now a REAL element-frame force (basic-`q` mapping, same as DispBeamColumn2d/3d) instead of a third spelling of the global vector. **Two name-lies fixed (BEHAVIOUR CHANGE, deliberate):** `localForce` on `LadrunoEmbeddedNode` used to be a second spelling of the global-component tie traction, which **shadowed the D9 local-frame branch and left that spelling permanently dead**; it now resolves to the local-frame one. On `LadrunoEmbeddedRebar` `localForce` is simply withdrawn — that element has no local frame, and the family reserves the spelling for one. **No vanilla footprint** — new header + fork-authored files only, so no [[LEDGER_vanilla_files]] rows.
