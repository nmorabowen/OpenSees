| **Analysis monitor** — live `recorder Monitor` that streams selected nodal scalars (disp/vel/accel/reaction per dof) to a SWMR-HDF5 sink a viewer process tails *while the run is still going* (`08_analysis_monitor.md`). Shape B (engine pushes from `record()` at each commit); two rate gates bound the data at explicit step counts — `-every K` step decimation + `-hz H` steady_clock wall throttle — so streaming never perturbs the solve (append is fire-and-forget, never blocks on a reader). One file, two lifetimes: the live sink is a valid at-rest results file. v1 = nodal scalar time-histories, sequential. Reuses NodeRecorder selection/response idiom; registered via the existing `recorder` command (type `Monitor`) so `addRecorder`/`remove recorder $tag`/tag-as-result come for free. **Viewer shipped (#487)** as `Ladruno_tools/monitor_viewer`, pure tooling on the unchanged sink: `monitor_reader.py` (`MonitorReader`, opens the sink per call in SWMR mode and refreshes, so it tails a file the solver is still writing; raises `FileNotFoundError` for a missing sink), `monitor_view.py` (matplotlib CLI: static plot, `--save`, `--channels`, `--x step`, `--watch` live tail) and `monitor_server.py` + `monitor_page.html` (FastAPI + a dependency-free live dashboard that polls `/api/frames?since=`; 503 until the sink exists); `test_monitor_view.py` is binary-free. It polls instead of the planned `/live` SSE and is its own page, not a React live mode in the profiler frontend. **Engine follow-ups from the #487 review fixed (#489):** node-removal safety (nodes re-resolved by tag on every emit, so a removed node no longer leaves a dangling `Node*`) and inertia-aware reactions (`-resp reactionIncInertia` / `rayleighForces`). `-overlay` p-field columns: see the LadrunoPorousOverlay row (#582).
