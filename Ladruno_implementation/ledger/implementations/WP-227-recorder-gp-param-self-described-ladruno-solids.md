| **WP-227 — Ladruno recorder: QUADRATURE/GP_PARAM for the Ladruno solids WP-226 left out** (#1067). **(1) LadrunoLST**: new arm Triangle_6N + `Triangle_GaussLegendre_2`, now tabulated in `getStandardQuadrature` in `lst_init_rule` order (2/3,1/6),(1/6,2/3),(1/6,1/6), w=1/6; `computeGlobalGP` gains a quadratic Lagrange T6 (LST/SixNodeTri node order). **(2) LadrunoSolidShell**: arm Hexahedron_8N + custom rule; the element answers `integrationPoints` / `integrationWeights` with its 2x2 x nz (gauss\|lobatto) set in its own layer-major loop order, so elements with different (rule, nz) land in different buckets. **(3) LadrunoUP**: five topologies under one class tag (its H8 GP order is bottom-CCW-then-top, NOT Brick's), so the arm is geometry Custom + custom rule and the element answers `basisInfo` + `integrationPoints` + `integrationWeights`; the writer derives the geometry PER BUCKET from the bucket's basisInfo (`geometryFromBasisInfo`), and node count / CSR are now per bucket, so a T3 + Q4 mesh writes two rectangular buckets (RBE3/RBE2 buckets that mix counts stay CSR). **(4) Bernstein**: `computeGlobalGP` gains Bernstein T6/Tet10 bases picked by FAMILY, so BezierTri6 and UP BT6/BTET10 get correct GLOBAL_GP_COORDS (also on curved elements) and BezierTet10's now uses its own basis instead of the Lagrange Tet10; a non-Lagrange family without a write-side basis gets none. **(5)** LST / SolidShell / UP per-GP responses (`stress`, `strain`, UP `stressTotal`/`porePressure`/`flux`) now emit GaussPoint tags, so DATA buckets per GP (GAUSS_ID 0..nGP-1) instead of one flat C1..Cn row. **(6)** `MPCORecorder.cpp`: LadrunoBrick / LadrunoQuad / LadrunoCST join the Hex GL2 / Quad GL2 / Tri GL1 arms. **Out of scope, documented:** LadrunoCSTPair (its GPs are the two sub-triangle centroids, which are not fixed points of the quad parent domain once the quad is distorted) and LadrunoCPML (no per-GP response at all).
