| **WP-108 — `-maxSubsteps`/`-honorTolR` ARE honoured on `LadrunoSANISAND` IntScheme 2; the constructor's own "NO EFFECT" warning was false** (WP-105 / F12 finding, PR #844 (open/unmerged), [[F12_intscheme2_verdict]] section 5.4/6) — `schemeReachesModifiedEuler()` used to return `false` for `mScheme == 2` (`INT_BackwardEuler`), so the constructor and `Print()` both warned that the substep cap and the TolR seam have NO EFFECT on scheme 2. Measured false: `BackwardEuler_CPPM`'s own recursive-halving retry ladder (`ManzariDafalias.cpp` ~2472-2588) falls back to `explicit_integrator` on non-convergence or ladder exhaustion, and that switch does not enumerate `INT_BackwardEuler`, so the call hits `default:` -> `ModifiedEuler` -- exactly where both seams are read. A `-maxSubsteps 100` cap on a `p -> p_min` floor path turned a run that completed 40 of 40 uncapped (up to 1282 substeps) into one that refuses at step 18 (WP-105). **Fix:** `schemeReachesModifiedEuler()` now also returns `true` for `s == INT_LSANISAND_BackwardEuler` (2), ahead of the existing `s > 9` catch-all; scheme 1's output is unchanged (the new branch is additive). The `LadrunoSANISAND_implex_guide.md` §3 scheme-2 bullet (which already REQUIRED `-maxSubsteps > 0` on scheme 2 and was therefore contradicting the warning) is reworded to state the fix, and the `LEDGER_quirks.md` WP-105 row is updated from "not fixed" to FIXED. | bugfix (one function, +docs +test) | — (no new class) | `SRC/material/nD/LadrunoSANISAND.cpp` (`schemeReachesModifiedEuler()` and its two call sites), `tests/test_ladruno_sanisand_intscheme2_maxsubsteps.py` (new), `Ladruno_implementation/LEDGER_quirks.md`, `Ladruno_implementation/LadrunoSANISAND_implex_guide.md` §3 | draft PR open | [#845](https://github.com/nmorabowen/OpenSees/pull/845) |
