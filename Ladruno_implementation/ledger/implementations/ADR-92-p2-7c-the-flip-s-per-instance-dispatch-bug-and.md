| **ADR-92 P2-7c — the flip's per-instance dispatch bug, and the flip absorption reversed to opt-in** ([[92_ladruno_sanisand_implex_adr]], LEDGER_quirks 2026-09-07) — THE DEFECT: `updateMaterialStage` writes `mElastFlag` (a STATIC shared by every `ManzariDafalias`/`LadrunoSANISAND` instance) correctly for all of them at once, but the DISPATCH that reaches `updateParameter()` -- vanilla `MaterialStageParameter::setDomain()`, `SRC/domain/component/MaterialStageParameter.cpp:68-77, NOT edited` -- walks the Domain's element iterator and STOPS at the first element whose `setParameter()` call returns anything but -1 (`while (((theEle = theEles()) != 0) && (theResult == -1)) theResult = theEle->setParameter(...)`). On the R3 footing (200 elements / 1600 Gauss points) this reached exactly element 1's 8 GPs -- elements 2 and 200 tracked `mElastFlag` correctly (the static) but P2-7's `updateParameter()`-hosted flip handling (deterministic `mAlpha_in`, the `mPrimed` guard-scope reset, the -implex companion) never ran for them, so 1592/1600 points ran the P2-7 REDESIGN'S OWN un-primed-guard defect it was meant to fix. FIX: `mFlipSeen` (bool, per instance) is the once-per-flip idempotency gate, now checked and set at the ONE point every instance passes through regardless of dispatch -- its own trial call, `ladrunoTrialUpdate()` -- via a new lazy trigger (`mElastFlag == 0` re-arms; `mElastFlag != 0 && !mFlipSeen` runs `ladrunoRunStageFlipOnce()`, the flip body factored out of `updateParameter()`, which is kept as a redundant FAST PATH for the one element the dispatch reaches, made idempotent by sharing the same `mFlipSeen` gate -- whichever of the two runs first for an instance marks it). `mFlipSeen`, unlike the `mStageFlipHandled` it replaces, crosses the wire (`Vector(30) -> Vector(32)` at data(31); 887fea475 did NOT send `mStageFlipHandled`, so a database-restored material re-ran the flip on a redundant `updateMaterialStage` re-assert), both `getCopy(const char*)` forms, and resets to false on `revertToStart`. TWO INTERFACE REVERSALS folded in on coordinator instruction, both BEFORE the C++ was measured against real analyses: (1) **`-flipAlphaIn` default flips `init` -> `vanilla`** (`FLIP_ALPHA_IN_VANILLA`, `init` now opt-in) -- Esmeralda measured that with the reversal-noise guard confined to PRIMED states (the `mPrimed` fix, unconditional and dispatch-independent regardless of this flag), vanilla's own loading-reversal sign test at the flip is NOT noise on a real deck: it is deterministic (28629/34560 R3-footing points set `alpha_in := alpha` at step 1, the same every run) and returns the implicit twin to the pre-P2 numbers to the digit (6.511/11.539/16.117/20.528 kN) -- so there was no defect to fix at the flip itself, only in the guard's scope, and the fork must not ship a modelling change as the default. `init` survives as an opt-in alternative Dafalias-Manzari modelling choice (an owner's RC14 request). (2) **`-implexFlipAbsorb on\|off` (new, default OFF)** gates the flip's own zero-pseudo-time-increment companion return (item 3, carried from the first P2-7 redesign) -- measured to break the ADR-92 gate-5 `-implex` ON-vs-OFF byte-identity on a zero-free-DOF deck (the flip commits nothing new under OFF; the absorption commits extra state under ON only), and Esmeralda confirmed the guard-scope fix alone is sufficient for the implicit-twin start with no absorption needed. `on` remains available for a deck that wants the drift correction anyway; default construction is therefore byte-identical to the pre-P2-7 build at the flip except for the `mPrimed` guard-scope confinement, which IS the real, retained fix. Cosmetic companion fix: the flip's own -implex companion commit (when `-implexFlipAbsorb on`) now saves/restores `mAlpha_n` around `ManzariDafalias::commitState()` -- Esmeralda measured 362/28629 points losing `\|alpha - alpha_in\| < 1e-9` equality post-flip under vanilla because the zero-increment return's stress-correction round-off moved `mAlpha_n` while `mAlpha_in_n` stayed exactly where the (neutral, dot==0) sign test left it; scoped to the flip's own companion commit only -- the general P2-3/P2-5c hold-preserving commit sites elsewhere were deliberately left untouched (broader blast radius, already-shipped/tested behaviour, outside this WP's mandate). Wire `Vector(30) -> Vector(32)` (data(30) = `mImplexOpt.flipAbsorb`, data(31) = `mFlipSeen`); `-implexFlipAbsorb` echoed at construction and in `Print()`, refused without `-implex` on the same rule as `-implexGuard`/`-implexTrialGuard`.
