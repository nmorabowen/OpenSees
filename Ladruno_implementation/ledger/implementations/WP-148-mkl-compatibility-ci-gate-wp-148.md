| **MKL-compatibility CI gate (WP-148)** — new job `mkl-compat` in `ladruno.yml`, running `ci/check_mkl_compat.py`: the MKL-gated sources must build against the OLDEST MKL a fork build uses, esmeralda's oneMKL 2024.2.2. The incident: WP-132 (#864) used `MKL_CBWR_AVX10` (oneMKL 2025.0+), which built on Windows (2025.1) while the Linux PARDISO opt-in stopped compiling, unseen for two days (#886), because Zone-A configures without MKL and never compiles `linearSOE/pardiso/`, the `_LADRUNO_MKL_FEAST` code or the `_PARDISO` blocks. The job unzips the PyPI `mkl` + `mkl-include` 2024.2.2 wheels into a private tree (pip-installing `mkl-devel` would put an `MKLConfig.cmake` on the root `find_package(MKL)` path), configures both Linux opt-ins with `CMAKE_EXPORT_COMPILE_COMMANDS`, then **M1** compiles every unit that touches MKL with its CMake command and **M2** checks with `nm` that every MKL symbol those objects reference is defined by the linked layers (`LADRUNO_MKL_LP64/SEQ/CORE`). M2 exists because the FEAST sources declare `dfeast_srci`/`feastinit`/`pardiso` by hand, so a too-new routine there compiles and only fails to link. It refuses to pass on nothing: the MKL version must be 20240002, and 5 required units must be compiled with their switch macro (`_LADRUNO_MKL_FEAST` / `_PARDISO`). `--self-test` compiles two canaries with a real unit's flags: the #864 line itself (must fail M1) and an undefined hand-declared routine (must fail M2). **Proven on its incident** (esmeralda, wheel MKL, `891978c9e`): exit 1 with `M1 PARDISOGenLinSolver.cpp:113 'MKL_CBWR_AVX10' was not declared`; with #886's `#ifdef` exit 0, 8/8 units, 9 symbols (`pardiso PARDISO MKL_CBWR_Get MKL_CBWR_Set MKL_CBWR_Get_Auto_Branch MKL_Get_Max_Threads feastinit dfeast_scsrgv dfeast_srci`). Configure 5 s + check 4 s there. **Same proof on GitHub's runner:** the PR's own run is red with the same M1 line ([run 36382915919](https://github.com/nmorabowen/OpenSees/actions/runs/36382915919)), and a `workflow_dispatch` of #886 + WP-148 is green, 5/5 units, 9 symbols ([run 36383278709](https://github.com/nmorabowen/OpenSees/actions/runs/36383278709)). The whole job is 43 s (the static gates take 44 s), so it runs on drafts. The runner has no MPI, so it sees 5 units, not esmeralda's 8 (no SP/MP copies). Merged after #886 (the guard), so it is green on `ladruno`.
