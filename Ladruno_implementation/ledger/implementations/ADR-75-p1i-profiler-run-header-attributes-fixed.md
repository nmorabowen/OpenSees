| **ADR-75 P1i — profiler run-header attributes fixed (`threads` / `nElem` / `nNode`)** ([[75_ladruno_sparse_direct_strategy_adr]] §9) — closes the *other* half of the §9 instrumentation item, found while measuring P1h and originally reported against ADR-76. **`threads` was the dangerous one:** `Profiler::buildMeta()` set `m.threads = threads_.size()`, the count of threads registered with the **profiler**, which is 1 for any run whose command layer is single-threaded — so a PARDISO run at `MKL_NUM_THREADS=4` recorded `threads=1`, and the ADR-76 reporter hit it at 8. A wrong positive integer is worse than no answer because it reads as a measurement. New `ops_profiler::resolveRunThreads()` resolves `MKL_NUM_THREADS` → `OMP_NUM_THREADS` → `hardware_concurrency()`, treating malformed/non-positive as UNSET (`strtol`, not `atoi`, so `"abc"` is distinguishable from a real 0 and MKL's nested `"4,2"` list reads as its outer value) and keeping the registered count as a **floor** so a genuinely threaded run can never under-report. New header `ProfilerRunMeta.h` then overrides it with `mkl_get_max_threads()` under `-D_PARDISO` — authoritative because it sees a programmatic `mkl_set_num_threads()` and reports **physical** cores when nothing is declared, which the env fallback can only estimate (`hardware_concurrency()` over-reports by the SMT factor). The header exists because the fix needs `Domain` (which `OPS_Utility` deliberately does not depend on) and MKL (whose `-D_PARDISO` is applied to the two **command** targets, not to `OPS_Utility`) — and because `profiler report`/`checkpoint` are implemented **four** times across two separate command ladders, so a shared helper is the only way this does not re-drift. **`nElem`/`nNode` were promised by a `Profiler.cpp` comment and populated by nobody** (only `nDOF` was) — now filled at all four sites. **`nnz` deliberately left 0:** `LinearSOE` has no size-agnostic nnz accessor, so filling it means a virtual on an upstream base class; a normalizer that exists for some solvers and not others is worse than one that never does. **`nSteps` is NOT a bug** — it is derived from the per-step series like `dt_min`/`dt_max`, so 0 without `-perStep` is correct (an earlier P1h draft called it a defect; corrected). Reporting-only; the `RUN_ATTRS_INT` schema (`Ladruno_tools/profiler_viewer/profiler_schema.py`) is unchanged, so existing viewers read the fixed values with no update.
