| **WP-235 — `hingeStatus` element response** on `LadrunoForceBeamColumn`, `LadrunoDispBeamColumn` and `LadrunoIMKBeam`, 2-D and 3-D. `hingeSummary` reads 0 for an absent hinge and for an unloaded one, and damage needed a different token per element and hinge type. `hingeStatus` always returns the same 8 columns, in `hingeSummary` slot order, also in 2-D (its Y slots are absent) and also on an element with no hinge: `kindZ_i, damageZ_i, kindZ_j, damageZ_j, kindY_i, damageY_i, kindY_j, damageY_j`. `kind`: 0 absent, 1 uniaxial law, 2 biaxial law. A biaxial law is one law per end, so it fills both the Z and Y slot of that end with kind 2 and the same damage; that is one value, not two. `damage` is the law's own `damage` response, unchanged; NaN when the slot is absent, the law has no `damage` response (Steel01, Bilin), or that response is not one scalar (snap `Bilinear`). The value is read from the live material on each call, through a `DummyStream` so material tags cannot become columns. `hingeSummary` is unchanged. | element response | **none new** — response id 36 on all six classes | SRC: `SRC/element/LadrunoHingeStatus.h` (new), `SRC/element/LadrunoResponseTokens.h`, the six `LadrunoForceBeamColumn{2,3}d.cpp`, `LadrunoDispBeamColumn{2,3}d.cpp`, `LadrunoIMKBeam.cpp`, `LadrunoIMKBeam2d.cpp`. tests: `tests/test_ladruno_hinge_status.py` (each family and dimension, checked against the per-material tokens and through `recorder ladruno` `COMP_NAMES`). docs: `Ladruno_implementation/200_ladruno_frame_elements_apegmsh_emitter_guide.md`.
