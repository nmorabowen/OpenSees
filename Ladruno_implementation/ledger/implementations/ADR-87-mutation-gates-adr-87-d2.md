| **Mutation gates (ADR-87 D2)** ([[87_ladruno_depth_with_width_adr]]) — CI machinery that makes "the tests are green" falsifiable. A mutation build sabotages ONE family's physics (`ZERO` internal force -> 0, `SCALE` x1.5, `IDENT` tangent -> I) and the family's suite must turn RED; the driver reports a **mutation score** (killed / baseline-passing) and, more usefully, the **survivor list** - tests that pass with the physics deleted. Design: call sites live in the Element API accessors (getTangentStiff/getInitialStiff/getResistingForce/getResistingForceIncInertia), i.e. the element<->solver contract, so ONE gate covers every formulation (LadrunoBrick's std/bbar/URI/physical/SSP/EAS/finite/hypo) and any future one; they are **always compiled** (never `#ifdef`-ed out) so a refactor breaks the build instead of silently disabling the gate; and mode NONE folds every branch to `if (0)` so a default build is unaffected. `ladrunoMutation` (both interpreters + classic Tcl) is the fail-loud wrong-build detector - the driver refuses to score a binary that cannot identify itself, because a silently-stale binary would otherwise make the gate report the exact opposite of the truth. First gate: CONTINUUM (LadrunoBrick + LadrunoBrick20). | test infrastructure | — (no class tag) | `SRC/Ladruno_mutation.h`, `Ladruno_scripts/mutation_gate.py`, `.github/workflows/ladruno_mutation.yml`, `tests/test_mutation_framework.py`; gates in `SRC/element/ladrunoBrick/LadrunoBrick{,20}.cpp`; verb in `SRC/interpreter/{OpenSeesOutputCommands.cpp,OpenSeesCommands.h,PythonWrapper.cpp,TclWrapper.cpp}`, `SRC/tcl/commands.cpp`; option in `CMakeLists.txt` | **framework shipped; CONTINUUM gate live and MEASURED** (run 33368686085, 210 baseline-passing tests): ZERO 137 killed / 73 survived = **0.652** (floor 0.60, PASS); SCALE 51 killed / 159 survived = **0.243** (informational). Read as a FLOOR on suite quality, not a verdict - the survivors split into (1) legitimately out of scope (~34: parser/guard, mass-matrix, geometry - the mutation targets the internal force, so these SHOULD survive), (2) **null-hypothesis tests that pass trivially on a dead element** (all assertions one-sided ~0, e.g. `test_corot_rigid_rotation_is_stress_free` asserts both stress and force <= 1e-7*E; remedy = positive controls), and (3) **beyond this gate's reach** (~35: the corot/finite/hypo lanes assert on `eleResponse("stresses")`, and `getResponse` reads `materialPointers[i]->getStress()` directly, never touching resid/stiff - so the gate covers the element->solver contract but NOT the element->recorder contract). WP-3: add a stress-path mutation point (cleanest at the material), then set a SCALE floor once categories 1 and 3 are out of the denominator; also adds UP/CONTACT/EXPLICIT/SANISAND. | WP-2 |
