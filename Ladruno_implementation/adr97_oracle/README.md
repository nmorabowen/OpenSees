# ADR-97 P0 — closest-point return map oracles

Reference implementations, in numpy, of the **closest-point (CPPM)** return map
and its **consistent (algorithmic) tangent** for the four `ASDPlasticMaterial3D`
families ADR-97 targets (von Mises, Drucker–Prager, Mohr–Coulomb, Hoek–Brown),
plus the path-independence gate and the element-level finite-difference driver that
measures the shipped binary against its own residual.

Everything here mirrors the **shipped headers**, not a textbook: tension-positive
stress (`meanStress() == trace/3`), Voigt order `[11 22 33 12 23 13]` with
engineering shear, VOIGT (doubled-shear) YF/PF derivatives (ADR-94 wp/94c B5),
`LinearIsotropic3D_EL` elasticity, and the truncated
`SQRT_2_over_3 = 0.816496580928` literal.  Each file's docstring names the header
lines it reproduces and records every convention wart found there.

Regenerate the transcript:

```
LADRUNO_OPENSEES_QUIET=1 \
PYTHONPATH=<worktree>/dist/bin \
python3.12 Ladruno_implementation/adr97_oracle/run_all.py    # -> reference_output.txt
```

Every gate is an `assert` inside the script, so a clean exit **is** the pass.

**Region scan** (400 trials, mixed compressive/tensile cloud): regions
`{face 129, line1 70, line2 3, apex 17}`; **max return-direction residual
`1.672e-14` with every Koiter multiplier ≥ 0**.  The elastic domain is convex, so
that residual vanishing with non-negative multipliers is a *proof* that no trial

apex, so an *absolute* 1e-10 gate is unattainable there — the HB instance of
ADR-94's `f_relative_tol` lesson.

**The tension branch is inert on the yield surface.**  `f_shear ≤ 0` already
forces `y1 ≤ T`, so the composite's zero set is the HB shear surface *plus its
own natural apex vertex*; the plane `y1 = T` never carries a face (0/4000 surface
points where `f_tension` wins; `min(f_shear − f_tension) = 1.004e-04`).
Outside the domain the tension branch wins exactly on `{y1 > T and y3 > T}`,
which **is** the header's `CHECK_APEX_REGION` set (0/4000 mismatches).  A Rankine
return onto `y1 = T` from `[645,265,255]` leaves `f_shear = +123.34` kPa
(2.31 % of `strength_scale`) — **inadmissible**.  So `Closest_Point` needs no
tension-plane return; the shear/tension corner *is* the apex.

**Apex region test.**  The exact (elastic-metric) apex region is
`apex + D3·(positive octant)` ⇔ `C3(x_tr − apex) ≥ 0` — exact, not asymptotic,
because the domain's tangent cone at the vertex is the negative octant (the HB
meridian meets the hydrostatic axis vertically).  The header's test is the
Euclidean octant `x_tr ≥ T`.  `D3·(octant) ⊂ octant` strictly, so the header
always **over**-claims the apex: 32 of the 400 scanned trials disagree, and on
`[645,265,255]` `APEX_STRESS` would commit `T·[1,1,1]` instead of the correct
face return — `|Δσ|_inf = 122.615448` kPa (2.292 % of `strength_scale`) of
silently lost strength (admissible, but wrong).

**g/f tension mismatch, quantified.**  `HoekBrown_PF::g` never negates to the
compression frame, so its branch `arg = mb_psi·σ3/σci + s` is built from the
tree's most *compressive* principal and is negative on any compressive state ⇒
`g` is always its `else` branch, a **Tresca** potential:

* the header's own central-difference `dg/dσ` at `[-2000,-6000,-25000]` is
  `[1,0,-1,0,0,0]` for `mb_psi = mb`, `mb/2` **and** `0` — `HB_mb_psi` has **no
  effect** and the flow is **non-dilatant** (trace exactly 0);
* against the frame-consistent `m = [4.65044, 0, -1]` (trace `+3.6504`) that is
  **32.86°** apart — and this is at `mb_psi == mb`, i.e. exactly where the deck
  asks for *associated* flow;
* same trial, same surface: `y = [-3642.77, -6441.62, -25123.72]` (plastic
  volumetric strain `+2.208e-05`) under the intended `g`, vs
  `y = [-3278.27, -6000.00, -23721.73]` (`-6.8e-21`, i.e. zero dilation) under
  the header's;
* at the apex **all six** shipped flow directions have negative trace
  (`trace(D3·m_ij) = -7.78e+08`), so the hydrostatic direction is **not** in the
  header-flow return cone (it is in the frame-consistent one).  A trial pushed
  past the tensile corner therefore has *no* return to the apex at all — the
  mechanism behind the residual recorded in `tests/test_adr94_hlist_hb.py`
  ("the drive still fails to converge on the step that would push strain past
  the tensile corner").

**Two formulation requirements for P3** (both measured in the transcript's
"near-apex conditioning" section):

1. **Use the surface's natural variable.**  With `y1` as the Newton unknown the
   map *diverges* near the apex: the surface exists only for `arg ≥ 0`, the
   first step from the elastic predictor overshoots (`arg = -2.2456e-03` at
   iteration 1) and the next Jacobian is singular.  Substituting `arg = w^(2/a)`
   (so `f = y1 − y3 − σci·w²`, `y1 = T − (σci/mb)·w^(2/a)`) is polynomial-smooth
   and feasible for *any* real `w` — no clipping, no line search, no feasibility
   guard.
2. **Normalize the flow direction** in the residual (`m/|m|`, multiplier rescaled
   by `|m|`; the returned stress is invariant).  `|m| ~ arg^(a-1)` blows up where
   the tensile returns land (`460.6` there vs `3.9` on an ordinary face point);
   worst-case Newton count over 400+ trials plus every FD stencil point is **6**
   un-normalized and **5** normalized.  The start guess adds the first-order
   cutting-plane multiplier `f/(a·D3·m̂)`, worth one more iteration.

Edges are returned by the two-surface Koiter system with the edge constraint
built into the parametrization (`f_13` and `f_23` share a root **iff** `y1 = y2`,
because `y − σci·arg(y)^a` is strictly increasing — so one surface row suffices).
Region selection needs no precomputed boundary planes: for a curved surface the
face/edge boundary is the ruled surface where the *face* return lands on the
edge, so the face return's own margins `y1−y2` and `y2−y3` are the exact signed
boundary functions (printed per trial).  Associated face tangent asymmetry
`|C−Cᵀ|/|C| = 6.285e-17`; the non-associated companion (`mb_psi = mb/2`,
frame-consistent `g`) gives `7.437e-02` with FD error `7.992e-11`.  The apex
tangent is the exact **zero** matrix, as for MC.

## Header findings recorded by these oracles

1. **AF hardening mixes conventions** (`AllASDHardeningFunctions.h:157`):
   `derivative = ha*mdev - cr*mdev_eq*alpha_dev` adds the ENGINEERING-shear
   (doubled) `mdev` to a STRESS-like back stress that is then consumed by
   `dev(sigma) - alpha` and `tensor_dot_stress_like`.  On sheared paths α's shear
   slots grow 2× relative to its normal slots.  There is also no `2/3` on `ha`
   (the `(2./3.)*ha` variants are commented out at lines 158–160).  The same
   policy still contains `cout` debug spam (lines 142–146, 152, 163) on every
   hardening evaluation.
2. **Drucker–Prager's cohesion IV is not in its own `f`**
   (`DruckerPrager_YF.h:26` is commented out) while `yf_hardening` contributes
   `df/dk = -1` times that IV's rate — a hardening term matching no term of `f`.
   The oracle pins the self-consistent `f = sqrt(J2) + eta*p - (xi_c + k)`.
3. **The DP / MC apex region tests are Euclidean, not elastic-metric** — the
   headers say so in their own comments; the numbers above quantify the cost.
4. **`MohrCoulomb_PF.h:83` converts the cohesion to radians**
   (`GET_PARAMETER_VALUE(MC_c)*M_PI/180`).  Harmless today only because `c`
   enters `g` as an additive constant that differentiation kills.
5. **`HoekBrown_PF::g` is evaluated in the un-negated (tension-positive) frame**
   (`PlasticFlowDirections/HoekBrown_PF.h:66`) while `HoekBrown_YF` negates first
   (`sigma_geo = -sigma`). `g`'s branch test therefore reads the most
   *compressive* principal, always falls into the `else` branch in compression,
   and degenerates to a Tresca potential: non-dilatant, independent of
   `HB_mb_psi`, and 32.86° off the surface normal even when the deck sets
   `mb_psi = mb`. Numbers in the HB block.
6. **The Hoek–Brown composite's tension branch is inert on the yield surface** —
   `f_shear ≤ 0` already implies `y1 ≤ T`, so `max(f_shear, f_tension)` closes
   only the hydrostatic-tension ray beyond the apex and adds no face. Its kink
   lies *inside* the elastic domain (at `y = [0,-500,-1000]`: `f_shear =
   -4350.427` vs `f_tension = -245.015`), where the header's central-difference
   `df/dσ` takes a chord across it.
7. **`HoekBrown_YF::CHECK_APEX_REGION` is Euclidean, and `D3·(octant)` is a
   strict subset of the octant**, so it always over-claims the apex and never
   under-claims: 32 of 400 scanned trials, worth up to `122.6` kPa of silently
   lost strength on the trial pinned in the HB block. Same defect class as
   finding 3, with a sign: the DP/MC tests misclassify in *both* directions,
   HB's in only one.
8. **`f`'s round-off floor diverges at the HB apex** (`|df/dy1| = 1 +
   a·mb·arg^(a-1)`), so an absolute `|f| ≤ 1e-10` yield gate is unattainable
   within ~1e-2 kPa of the apex. Scale the tolerance by the gradient — the HB
   instance of ADR-94's `f_relative_tol`.
9. **Mohr–Coulomb has no edge/apex algebra at all**: for `|theta| >= 29°` the
   header silently substitutes a Drucker–Prager gradient, and the default path is
   a numerical central difference of `f`.  `cppm_mc.py` is the reference for what
   `Closest_Point` must do instead.
