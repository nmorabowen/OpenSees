## Specific questions for the reviewer

1. **Step order and failure semantics.** A kernel refusal (`det F_mid ≤ 0`) or a material trial
   failure reverts every particle material already set and returns -1 before any commit; the host then
   calls `Domain::revertToLastCommit()` to undo step 2's time advance. A refusal at commit (-2) is read
   from the WP-99 counter by the host itself (so `Domain::commit` never sees it) and aborts with
   particles unmoved. Is consuming the counter in the host, instead of leaving it to
   `Domain::commit`, sound under W17?
2. **Critical Δt from the "committed" tangent (A5 F6).** `normalModulus` calls `NDMaterial::getTangent()`
   between steps, i.e. after commit or after a revert. Is there an admitted material whose
   `getTangent()` after `commitState()` is not the committed tangent?
3. **Ghost layers.** One layer, by the argument |x_p − x_i| < h + lp ≤ 1.5h with the centre in the real
   grid. Conditions apply to `ijk[d] ≤ 0` / `≥ n_d`. Any case — corners, a wall plus a fix on adjacent
   faces — where the face-order rule (walls in face order, then fixes) differs from the interface?
4. **Initial stress (interface Q2, 232c's design).** v1 accepts an initial stress only on
   `ElasticIsotropic` (an exact additive offset in the unrotated frame) and refuses it on LadrunoJ2 and
   DruckerPrager. Is refusal the right v1 answer, or should yield-consistent seeding come now?
5. **Admission by class tag of the copy** (`admitMaterial`, `LadrunoMPMPattern.cpp:211`). LadrunoJ2's
   `-autoRegularization` is detected through a new accessor `usesAutoRegularization()` in
   `LadrunoJ2.h`. Any admitted material that still reads `ops_TheActiveElement` with it zeroed?
6. **The `parameter … loadPattern` path.** The host forwards `setParameter` to every particle material;
   each registers itself, so `updateParameter` reaches the materials directly. After `mpm reset` the
   materials are the same objects (`revertToStart`), so parameters survive. After `remove loadPattern`
   they dangle, as for removed elements upstream. Acceptable for v1?
7. **Free FE DOFs refusal.** A node DOF counts as fixed only through a domain or pattern SP; an
   MP-constrained DOF counts as free. Too strict, or right for v1 (no FE–MPM seam)?
8. **Classic Tcl output precision.** `OPS_SetDoubleOutput` prints `%35.20f` in classic Tcl (quirk
   fragment `WP-232-tcl-double-output-fixed-point.md`); the parity test uses an absolute floor. Does any
   user-facing value (`mpm criticalTimeStep` for a stiff, fine grid) lose digits that matter?
