## H10 — verdict

**CONFIRMED, split severity.**

**H10a (Hoek-Brown drift) — CONFIRMED, MEDIUM severity, tension-only.**
- Deciding observation: `test_H10_hb_tension_locks_onto_wrong_plateau_then_stalls`
  — a uniaxial-stress tension path on realistic rock parameters (sigci = 50
  MPa, mi = 10, GSI = 60, D = 0) commits stress at 587.19 kPa, `mb` = 2.397x
  the textbook tensile strength (245.02 kPa), because this tree's HB yield
  function has a genuine discontinuity at `arg = mb*sigma3/sigci + s = 0`
  (the if/else branch switch) that jaabell's later `60d9b9b23` composite
  `max(f_shear, f_tension)` does not have. The analysis then stalls
  (`analyze() == -3`) at that wrong plateau.
- Blast radius: every registered `HoekBrown_YF` combination (7 of the 46
  registered ASDP materials) on any load path that reaches hydrostatic
  tension beyond `sigma_t` — i.e. any rock model in net tension (unloading
  of an excavation face, thermal/shrinkage tension, a tension-side seismic
  swing). Compression-dominated rock/tunnel/slope work is unaffected: the
  two trees are bit-identical there (§(b) of the drift doc; pinned by
  `test_H10_hb_uniaxial_compression_matches_closed_form_ucs` and
  `test_H10_hb_triaxial_compression_stays_admissible`).
- Recommendation: port jaabell's composite (§(c) of the drift doc); not
  performed in this ADR (D1: plan only). Gated on the D4 exchange with José.

**H10b (DruckerPrager apex stub) — CONFIRMED, HIGH severity, silent NaN.**
- Deciding observation: `test_H10_dp_apex_hydrostatic_tension_commits_nan`
  — a pure hydrostatic-tension path (zero deviatoric stress throughout,
  the exact degenerate case apex handling exists for) through `p =
  xi_c/eta` = 3333.33 kPa commits **NaN stress while `analyze()` keeps
  returning 0 (success)**. This is worse than "apex unhandled": it is a
  silent numerical corruption that no existing check (not even
  `strict_convergence`, ADR-84 P2a) catches, because NaN comparisons are
  always false — `std::abs(Phi) < tol_yf` and every f-sign check in
  `Backward_Euler` silently evaluate to "not converged / not elastic" or
  "converged" unpredictably once `Phi` itself is NaN, so nothing in the
  existing gates trips.
- Root cause, precisely: `DruckerPrager_YF::CHECK_APEX_REGION` is a stub
  (`DruckerPrager_YF.h:105-111`, `// Implement!!!`, `return false`) despite
  `yf_has_apex<DruckerPrager_YF<...>> = true_type` being declared
  (`DruckerPrager_YF.h:136-137`). But the stub alone would only mean "no
  special apex return is attempted" (falls through to the generic
  Backward_Euler loop) — it would NOT by itself explain a NaN, because the
  generic loop's own epsilon guard
  (`DruckerPrager_YF.h` derivative, `if (abs(den) > 100*eps) ... else
  dev_part *= 0.0`) degrades gracefully to a pure-volumetric flow direction
  at zero deviatoric stress. The actual NaN source is upstream of the apex
  question entirely: **the Backward_Euler apex-return call site in
  `ASDPlasticMaterial3D.h` (~2093-2161,
  `if constexpr (yf_has_apex<YieldFunctionType>::value) if
  (yf.check_apex_region(...)) { /* entire body commented out */ }`) is dead
  code for every yield function, DP and HoekBrown alike** — so even a fixed
  `CHECK_APEX_REGION` would change nothing today without also reviving that
  call site (a larger fix, correctly out of this ADR's scope per D1). With
  neither the stub fixed nor the call site alive, the plastic-correction
  loop is left to solve the scalar consistency equation through the
  literal cone vertex using ordinary floating-point arithmetic on a
  problem that is analytically singular there (the tangent stiffness at
  `q=0, p=p_apex` is not invertible in the direction the correction needs),
  and it produces NaN rather than diverging loudly.
- Blast radius: every registered `DruckerPrager_YF` combination (14 of 46)
  on any load path that reaches net hydrostatic tension at `p >= xi_c/eta`
  — most plausibly a near-surface / low-confinement soil element unloading
  into tension (excavation, seismic uplift), or any decomposition
  (LadrunoCMS, staged construction) that momentarily zeros confinement.
  Sanity twin `test_H10_dp_apex_hydrostatic_compression_stays_admissible`
  confirms the NaN is apex-specific, not a generic hydrostatic-loading bug
  (the compression side of the same cone stays finite and admissible for
  the identical strain magnitude).
- Recommendation: implement `CHECK_APEX_REGION`/`APEX_STRESS` for DP AND
  revive the `ASDPlasticMaterial3D.h` call site (both are required — one
  without the other is a no-op, as this finding demonstrates for
  HoekBrown, whose apex methods ARE implemented and are still inert). This
  is upstream-facing framework work (changes Backward_Euler's behaviour
  for every apex-capable YF), not a fork-only fix — coordinate with José
  per the ADR-84 "bit-identical strategy" precedent. Not performed in this
  ADR (D1: plan only); candidate for its own `wp/94x-<slug>`.
